## Goal

Вынести движок фотосайта в публичное версионируемое ядро — Astro-интеграцию, npm-пакет `@picasso-ai/astrum-scena` — с демо-сайтом, который ставит ядро из упакованного артефакта так же, как настоящий сайт. Эпик фиксирует публичный API со снапшотами, конфиг переопределений с lock-файлом, контракты темы и словарей, модули с манифестом, CLI со skills и пресетами, переиспользуемый CI и гейт идентичности перед публикацией. Итог: тонкий сайт кастомизирует ядро только через API и обновляется сменой версии, а в публичном репо нет следов исходного сайта и его владельца. Остаточный долг эпика 5, привязанный к 6.2, 6.5, 6.8 и 6.9, учитывается при детализации этих историй; пробная сборка 6.8 породила 6.13 и 6.14, которые закрываются до первого сайта (9.1). Историю 6.9 завершает публикацию: у каждого чужого ассета известна MIT-совместимая лицензия, первую версию в npm владелец публикует вручную, затем выпуски идут из CI без токена.

## Requirements & Constraints

- Ядро публично только после зелёного гейта идентичности: ни доменов, имён, аккаунтов, ID бакетов, локальных путей, ни конфига и контента исходного сайта. Фикстуры, эталоны, корпуса и фото демо синтетические.
- Опубликованный вывод сайта не меняется; визуальные эталоны и e2e зелёные. Контент сайта не переписывается.
- Стек: Astro static, TypeScript 6, Tailwind v4. Инфраструктура, секреты и окружение принадлежат сайту; ядро знает только имена переменных и ключей.
- Тесты ядра работают на фикстурах и демо и не пинят значения реального конфига; e2e выводят ожидаемое из конфига и словарей демо. Исходный сайт заморожен и читается только для проверок на реальном конфиге и пробной сборки.
- Каждый контракт имеет ровно один авторитетный гейт; любой тест или проверка входит в `pnpm check` или CI.
- Хеш изображений и другие значимые байтовые контракты не меняются от смены формы конфига или данных.
- Файлы, которые пишет ядро и побайтно сверяет гейт (`site.lock.yaml`, `images-public.json`, установленные skills и агенты), не должны ломаться `prettier --write` сайта: либо писатель выдаёт форму пресета Prettier, либо `install` исключает файлы из Prettier сайта; смена их байтов — ломающая по политике версий.
- Обработчик контактной формы, охрана хоста и тип окружения — публичный экспорт ядра; обёртка Pages Function сайта не использует глубокий импорт.

## Technical Decisions

- **Поставка.** Публичный npm с trusted publishing; core и migrate-wp идут общей версией. Демо в CI ставится из `pnpm pack`, вне workspace. Релизный workflow пропускает уже опубликованную версию; до публикации — только `--dry-run`. Первую версию владелец публикует вручную с 2FA и настраивает trusted publisher (с разрешённым действием `npm publish`); затем шаг `main` в `release.yml` идёт без `--dry-run`, а guard-тест, требующий `--dry-run`, удаляется.
- **Корни путей.** Ресурсы ядра адресуются от установленного пакета, файлы сайта — от корня сайта из интеграции, никогда не от `process.cwd()`. Вычисления получают входы явно и не импортируют IO/Astro-адаптеры; разделение — по пользе, без тотальной переработки `lib`.
- **Публичный API.** `exports` (глубокий импорт запрещён lint-правилом), схемы файлов сайта, имена MDX-компонентов и директив, токены, i18n-ключи, команды CLI и env. Внутренние переменные runners и тестовые протоколы в API не входят. Снапшот-гейты валят CI до обновления снапшота в том же PR.
- **Версии.** Ломающее — то, что требует правки конфига, контента или кода сайта либо перевыпуска деривативов. npm-версия ядра `0.x` до первого сайта — `0.<эпик>.<история>` выпускающей истории, первая публикация `0.6.9` (ломающим может быть любой более высокий выпуск со своим разделом в `UPGRADING.md`, сайт закрепляет версию точно), затем semver; репо и CHANGELOG продолжают `1.<epic>.<story>`. Каждый ломающий переход описан в `UPGRADING.md` с примерами «до/после» и проверкой; универсальной команды обновления нет.
- **`schemaVersion`.** Каждый читаемый ядром файл сайта несёт `schemaVersion`; отсутствующая или неподдерживаемая версия — ошибка с именем файла и списком поддерживаемых. Контентные коллекции версионируются одной записью в lock.
- **Конфиг.** `site.yaml` — только переопределения; `core config resolve` пишет строгий `site.lock.yaml`, который читают сборка и команды через один загрузчик; drift-гейт сверяет lock. Неизвестный ключ — ошибка с путём. Хеш изображений считается от проекции полей с `digestVersion`.
- **Локали и перечни.** Локали, опорная локаль и origin — только в конфиге; интеграция падает, если `astro.config` задаёт `site` или `i18n` в обход. В ядре нет литералов локалей вне слоя конфига; каталог локалей выводится из конфига (умолчания ядра для `en`/`ru`, переопределение и дополнение в `site.yaml`, типографские константы входят в запись каталога, запись сервисной локали обязательна); локализуемые данные — записи по локалям из конфига, лишняя или пропущенная локаль — ошибка. Категории, виды мест и тегов, негеографические измерения — конфиг с умолчаниями ядра.
- **Тема и i18n.** Тема задаёт только экспортированные токены; неизвестный токен или точка замены — ошибка; layout-токены генерируются из конфига. Ядро и модули дают словари по умолчанию, словари сайта частичные; пропущенный ключ в любой локали — ошибка сборки без отката.
- **Модули.** Манифест объявляет коллекции, сегменты маршрутов, `modules.<id>`, i18n-пространство, MDX-имена, токены, меню и зависимости. Курсы — эталонный модуль. `src/content.config.ts` сайта — один вызов построителя ядра. Без модуля нет его маршрутов, коллекции и sitemap; его контент — ошибка; коллизия имён валит сборку.
- **Операции.** CLI ядра поставляется собранным JS; у сайта только тонкие алиасы. Skills, пресеты и блок `AGENTS.md` ставятся командой ядра со штампом версии; skill сайта не занимает имя skill'а ядра.
- **CI.** CI сайта — переиспользуемый workflow ядра по тегу и SHA, без `secrets: inherit`. Гейт падает при расхождении тега workflow или штампа skills с установленным ядром и на `pnpm link` в CI.
- **Идентичность.** Общие шаблоны — в репо; конкретные строки владельца — только в gitignored-файле и секрете CI; без них гейт падает в CI, а вне CI проверяет только шаблоны с предупреждением. `check:local-paths` работает постоянно. Гейт идентичности сканирует всё дерево, включая `docs/`, `_bmad-output/` и имена файлов, без исключённых каталогов. Публичный репо создаётся из одного orphan-коммита после зелёного гейта, локального прогона по списку владельца и сканера секретов; планирование сайта (эпики 1–5 и 9, история миграции) к этому моменту вынесено в его приватный репо, в ядре остаются очищенные планы эпиков ядра и ADR.

## UX & Interaction Patterns

- Редизайн вне скоупа. Кастомизация — тема, настройки и небольшой набор именованных визуальных точек замены с типизированными пропсами и слотами. Интерактивная оболочка и её DOM остаются у ядра.
- Демо показывает одну замену; e2e проверяет взаимодействия, клавиатуру и переходы ClientRouter. Список DOM-хуков доказательством не считается.
- При одной локали нет переключателя языка, альтернатив `hreflang` и свежести перевода на `/status/`.

## Cross-Story Dependencies

- 6.1 и 6.1b — входы для 6.2: канал поставки и граница источников Tailwind. 6.2 — база эпика: перенос кода, разведение корней, гейты исходников и демо. Части 6.2 идут по очереди.
- 6.3 фиксирует API и `schemaVersion` до 6.4–6.7. Lock из 6.4 нужен 6.5, 6.6, 6.10 и 6.11. 6.6 опирается на правила полноты словарей из 6.5; её часть B расширяет API-снапшот.
- 6.7 переносит GPS-код мест через общий загрузчик мест; 6.7 и 6.8 связаны штампом версии и запуском CLI из lockfile. 6.8 включает пробную сборку контента исходного сайта на ядре.
- 6.12 заменяет заглушки в демо и переснимает визуальные эталоны. 6.9 завершает эпик и требует чистоты всех историй; до orphan-коммита планирование сайта выносится в его приватный репо.
- За пределами эпика: эпик 7 — документация и процедура расширения; эпик 8 — migrate-wp на той же версии; эпик 9 — первый сайт принимает ядро, и npm-версия переходит на `1.0.0`.
