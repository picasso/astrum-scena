## Intent

**Problem:** Не выбран канал, через который сайт ставит и обновляет ядро. От него зависят структура
репо ядра, релиз и CI сайта (6.2–6.9); ошибка выяснится только после выноса. Вопрос открыт в
[SPEC](../specs/spec-core-and-thin-sites/SPEC.md#open-questions).

**Approach:** На учебном пакете в отдельном репо практически сравнить три канала — git-теги с
`#semver:`, GitHub Packages, публичный npm — на pnpm 11.14 и Astro ^7.1 проекта, проверить
Astro-интеграцию из пакета и реальную цепочку `variantCssPlugin` из установленного tarball. Выбор и
ограничения записать ADR'ом; найденные зависимости от размещения — для исправления в 6.2.

## Boundaries & Constraints

**Always:** Учебный код и контент синтетические: без доменов, имён, ID Cloudflare, локальных путей и
контента `<site>`; исключение — копия `src/lib/variant-css.ts` и четырёх каталогов вариантов CSS
для проверки цепочки. Каждый вывод матрицы подкреплён командой, логом или ссылкой на прогон CI.
Проверка CI идёт с `GITHUB_TOKEN` воркфлоу, без личного токена в секретах.

**Решение владельца (репо):** два публичных учебных репо `<owner>/core-delivery-spike` (пакеты) и
`<owner>/core-delivery-spike-site` (потребитель); приватный случай 6.2–6.9 — один прогон с временно
закрытым репо пакетов. Репо нужны только на время спайка и в конце удаляются, поэтому ADR хранит
доказательства в тексте (команды, выдержки логов), а не только ссылками на прогоны.

**Решение владельца (npm):** настоящая публикация учебных пакетов в публичный npm под scope аккаунта
владельца (`npm whoami`), с нейтральными именами `delivery-spike-*` и версиями `0.0.x`; публикация
из CI учебного репо проверяется через trusted publishing. Все версии снимаются `npm unpublish` в
пределах 72 часов.

**Решения владельца после спайка (2026-10-25):** версия `core` и `migrate-wp` общая, как в AD-20 —
независимые версии не нужны, строка матрицы о них на выбор не влияет. Приватный период 6.2–6.9 на
выбор канала не влияет: сравнение — для публичного ядра. Канал — публичный npm с trusted publishing.

**Never:** Не менять код `<site>` (исправления — 6.2), не создавать репо ядра (6.2), не делать
коммиты, R2-записи и деплой. Не публиковать ничего под именами будущего ядра.

## Code Map

- `src/lib/variant-css.ts` — `root` (сейчас `process.cwd()`) служит и для CSS пакета
  (`VARIANT_CSS_DIRS` = `src/components/...`), и для альбомов потребителя (`ALBUMS_DIR`); это главный
  кандидат в зависимости от размещения. `everyVariantCss` читает каталоги CSS тем же корнем.
- `astro.config.mjs:28–108` — все загрузчики и плагины получают `process.cwd()`; `CONFIG_YAML_BY_MODULE`
  резолвит относительно cwd. Это потребитель, его поведение описывается, но не меняется.
- `src/styles/global.css` — `@import 'tailwindcss'` без `@source`; граница сканирования решается в
  BK17 до 6.2, спайк проверяет только `@source` на пакет.
- `package.json` — `packageManager: pnpm@11.14.0`, `astro ^7.1.1`, `react ^19.2.7`, `@astrojs/mdx ^7`,
  `tailwindcss ^4.3.3`; учебный пакет берёт те же версии. `pnpm-workspace.yaml` — `allowBuilds`.
- `docs/adr/README.md` — формат и реестр; следующий номер 0016.
- Предусловия: `gh` с правами `repo`, `write:packages`, `read:packages`, `delete:packages` (без
  `delete_repo`); npm авторизован владельцем scope `@picasso-ai/`. Удалённые операции разрешены владельцем только
  над двумя учебными репо и пакетами `delivery-spike-*`; каждая команда называет репо или пакет
  полностью; в `<site>` — ни push, ни коммитов.
- Строки I/O-матрицы покрываются доказательствами в ADR-0016 (команда и выдержка лога из учебного
  репо), а не тестами `<site>`.

  на время спайка созданы `.claude/allow-push` в корне `<site>` и в учебном репо (оба исключены

  прервалась на включение 2FA). После повторной настройки владельцем оба пакета выпущены из CI без
  токена; ADR-0016 переписан под выбор владельца — публичный npm.
- Уборка 2026-10-25: пакеты GitHub Packages удалены, оба репо архивированы, `/tmp/delivery-spike` и
  `.claude/allow-push` в `<site>` (вместе со строкой `.git/info/exclude`) удалены. Остаётся за
  владельцем: `npm unpublish` обоих пакетов с 2FA до ~2026-10-27 18:30 UTC, удаление токена
  `delivery-spike`, удаление двух репо.
- 2026-10-25: владелец выполнил свою часть уборки — оба пакета npm отвечают `E404`, оба репо удалены,
