# MoreDocuments: связанные материалы после документа

- **Статус:** согласованный контракт, реализация впереди
- **Обновлено:** 2026-08-26
- **Область:** переиспользуемое Astro-ядро для нескольких сайтов

## Назначение

`MoreDocuments` — автоматически собираемая навигационная секция после основного содержимого
документа. Она показывает другие статьи, туры, обычные страницы или материалы новых типов, которые
будут зарегистрированы на следующих сайтах.

Это **не контентный MDX-блок**. Редактор не вставляет компонент в Markdown и не управляет его HTML.
Секцию добавляет обвязка detail-страницы после тела документа и относящихся к нему служебных строк,
например копирайта. Состав разрешается на сервере во время статической сборки, итогом становится
обычный HTML без клиентского JavaScript.

Один механизм закрывает два сценария:

1. Автоматический список других опубликованных документов того же типа.
2. Ручную ссылку на один или несколько конкретных документов любых зарегистрированных типов.

Визуальные примеры legacy на исходном сайте:

- More Articles под статьёй —
  четыре карточки с изображениями и без анонсов;
- More Tours под страницей тура — вертикальный список с изображениями и анонсами;
- одиночная ссылка в About — вырожденный ручной список
  из одного документа без видимого заголовка.

Согласованный контракт имеет приоритет над текущей временной реализацией и старыми выводами аудита.

## Реестр типов документов

Механизм не должен знать фиксированный union `articles | courses`. Сайт предоставляет расширяемый
реестр семантических типов `kind`. Запись реестра связывает тип с источником контента, правилом
отбора, построителем маршрута, доступными полями и локализованными подписями.

Для текущего сайта нужны три типа:

| `kind`    | Источник                                                 | Маршрут                      | Поддерживает `newest` |
| --------- | -------------------------------------------------------- | ---------------------------- | --------------------- |
| `article` | коллекция `articles`                                     | `/{locale}/articles/{slug}/` | да                    |
| `course`  | коллекция `pages`, только `kind: course`                 | `/{locale}/courses/{slug}/`  | нет                   |
| `page`    | коллекция `pages`, только страницы без специального kind | resolver обычных страниц     | нет                   |

Следующий сайт может добавить `news`, `book`, `event` или другой тип без изменения контракта
`MoreDocuments`. Хранилище не выставляется наружу как `collection`: редактор работает с предметным
`kind`, а реестр скрывает конкретную Astro-коллекцию и схему маршрута.

### Локализованные подписи

Заголовок и доступное имя навигации принадлежат реестру типа текущего документа, а не frontmatter.

| `kind`    | RU                    | EN                |
| --------- | --------------------- | ----------------- |
| `article` | `Другие статьи`       | `More Articles`   |
| `course`  | `Другие туры`         | `More Tours`      |
| `page`    | `Связанные материалы` | `Related content` |

Даже при ручном смешанном списке подпись определяется типом **текущего** документа. Тип каждой
целевой карточки отдельным бейджем не показывается.

## Конфигурация сайта

Каждый зарегистрированный тип получает собственную обязательную конфигурацию представления. Она не
наследуется от индекса или архива этого типа: список на detail-странице является отдельной
поверхностью.

```ts
type MoreDocumentsConfig = {
	source: 'siblings' | 'off'
	layout: 'grid' | 'masonry' | 'list'
	width: 'prose' | 'medium' | 'wide'
	heading: 'on' | 'off'
	media: 'on' | 'off'
	excerpt: 'on' | 'off'
	card: 'details' | 'title-strip' | 'title-slide'
	ratio?: 'pano' | 'vista' | 'landscape' | 'square' | 'portrait' | 'original'
	columns?: number
	gap?: number
	order?: 'newest' | 'title'
	limit?: number | 'all'
}
```

Все перечисленные переключатели задаются явно: скрытых defaults для `media`, `excerpt` и других
визуально значимых решений нет.

### Условные поля

- `source: siblings` требует `order` и `limit`.
- `source: off` запрещает `order` и `limit`.
- `layout: grid` и `layout: masonry` требуют положительный целочисленный `columns`.
- `layout: list` запрещает `columns`.
- `gap` — отступ между карточками в px (`0..64`); обязателен для `grid` и `masonry`, запрещён для
  `list`.
- Кроп превью с фиксированной `ratio` идёт по `focalPoint` фото-обложки (по умолчанию центр) — тот же
  общий `Card`, что у карточек Portfolio и индексов документов.
- Смысл `columns` зависит от раскладки: в `grid` это точное число колонок, когда ширина блока не
  меньше `720px` (уже — колонки подбираются автоматически, не уже `220px`); в `masonry` — максимум
  колонок.
- `media: on` требует `ratio`.
- `media: off` запрещает `ratio`; зона изображения полностью отсутствует.
- Для `masonry` допустим только `ratio: original`.
- Для `grid` и `list` допустимы `pano`, `vista`, `landscape`, `square` и `portrait`.
- `card` — тот же набор видов, что у `portfolio.card`: `details` (миниатюра,
  название, excerpt), `title-strip` (миниатюра и полоса с названием под ней), `title-slide` (название
  плашкой поверх миниатюры: выезжает по hover/focus, на touch видно всегда). Компактные виды требуют
  `layout: grid` или `masonry`, `media: on` и `excerpt: off`; у документа без обложки плашка ложится
  поверх стандартного placeholder.
- `order: newest` разрешён только типу, в реестре которого объявлена дата публикации.
- Числовой `limit` — положительное целое. `all` снимает ограничение; искусственного максимума пула
  нет.

### Текущая конфигурация сайта

Фактические значения живут только в [`src/config/site.yaml`](../src/config/site.yaml) (ключ
`moreDocs`) вместе с комментарием к каждому параметру; здесь они не дублируются, чтобы документ не
устаревал при каждой настройке владельца.

Значения `width` выбирают токены дизайн-системы:

- `prose` — текущий контейнер до `680px`;
- `medium` — документная ширина до `960px`;
- `wide` — стандартный широкий контейнер до `1200px`;
- на узком экране оба используют общие адаптивные внешние поля.

Числа ширины не принадлежат компоненту. На другом сайте те же семантические значения можно связать
с другими токенами.

## Настройка отдельного документа

При отсутствии `moreDocs` используется `source` из конфигурации текущего `kind`.

### Отключение секции

```yaml
moreDocs: off
```

Значение отключает секцию только на текущей странице. Оно не исключает этот документ из пула
`siblings` на других страницах. Отдельного флага исключения из пула пока нет: в нём участвуют все
опубликованные документы нужного типа.

### Ручной список

```yaml
moreDocs:
    docs:
        - kind: page
          slug: related-page
```

`docs` принимает один или несколько элементов. Один элемент является обычным списком длины один;
отдельного режима `single` нет.

Правила ручного списка:

- он полностью заменяет `siblings`; автоматическое дополнение до `limit` запрещено;
- порядок карточек равен порядку элементов в `docs`, сортировка не применяется;
- `limit` не применяется, ручной список всегда выводится полностью;
- оформление наследуется от конфигурации `kind` текущего документа;
- список может смешивать документы разных типов;
- пустой `docs: []` невалиден;
- повтор одной пары `{ kind, slug }` невалиден;
- внешний URL вместо управляемой ссылки не поддерживается.

`slug` — slug материала внутри зарегистрированного `kind`, а не URL. Он записывается без начального
и конечного `/` и без языкового префикса. Resolver типа строит итоговый маршрут. Ссылка разрешается
строго в текущей локали, без fallback на другую. Если локализованные версии используют разные slug,
каждый языковой frontmatter указывает своё значение.

Ручная ссылка на отсутствующий `kind` или slug, черновик, отсутствующую локаль либо текущий документ
является ошибкой сборки. Ошибку нельзя заменять молчаливым пропуском карточки.

> В About вручную добавлена ссылка на опубликованную страницу `almost-autobiography`.

## Автоматическая выборка `siblings`

`siblings` означает все другие опубликованные документы того же зарегистрированного `kind`.
Алгоритм детерминирован:

1. Взять опубликованные документы текущего типа и локали.
2. Исключить текущий документ.
3. Применить `order`.
4. Применить числовой `limit` или оставить весь набор при `all`.

`order: newest` сортирует дату публикации по убыванию. `order: title` сортирует локализованный
заголовок по алфавиту, поэтому порядок RU и EN может различаться. При равенстве основного ключа slug
служит детерминированным tie-break.

Если найдено меньше `limit`, выводится доступное количество без заполнителей. Если не найдено ни
одного документа, вся навигация, включая заголовок, отсутствует в HTML.

## Модель карточки

Карточка использует общую модель документных карточек сайта:

```ts
type MoreDocumentCard = {
	href: string
	title: string
	excerpt?: string
	media?: PictureModel
}
```

Вся карточка является внутренней ссылкой и открывается в текущем окне. Специальных надписей типа
материала и отдельной ссылки «читать дальше» у этой поверхности нет.

### Анонс

При `excerpt: on` используется стандартный resolver анонса документа: сначала authored `excerpt`,
затем уже принятая для карточек деривация из тела. Если после разрешения анонса нет, карточка
остаётся без него; это не ошибка. При `excerpt: off` анонс не вычисляется и не рендерится.

### Изображение

При `media: on` берётся стандартное управляемое репрезентативное изображение документа — то же
редакторское назначение, которое используют другие карточки и анонсы. Отдельного изображения только
для `MoreDocuments` и произвольного внешнего URL нет.

Если назначение отсутствует, выводится общий placeholder сайта с той же зарезервированной геометрией,
что у обычной картинки. Это сохраняет сетку и текстовую колонку списка. При `media: off` placeholder
не нужен: медиазона удаляется, а текст занимает доступное пространство.

`landscape`, `square` и `portrait` задают рамку превью; изображение заполняет её через
`object-fit: cover`, не изменяя исходный файл. `original` сохраняет исходное соотношение сторон и
предназначен для masonry.

Все превью автоматически:

- получают `loading="lazy"` и асинхронное декодирование;
- используют управляемые деривативы, `srcset` и рассчитанный для поверхности `sizes`;
- получают intrinsic `width` и `height`, чтобы не вызывать layout shift;
- используют общий resolver `alt` управляемого изображения.

`sizes` выводится из `layout`, `width` и `columns`; редактор его не задаёт.

## Раскладки и адаптивность

### `grid`

Равномерная сетка карточек с одинаковым `ratio`. `columns` задаёт **максимум**, а не обязательное
число колонок на любом широком экране. Через container queries компонент выбирает наибольшее число
от `columns` до `1`, при котором карточка не становится уже общей минимальной ширины card-токена.
Например, `columns: 4` может пройти `4 → 3 → 2 → 1` по мере сужения фактического контейнера.

### `masonry`

Кладка сохраняет исходные пропорции изображений (`ratio: original`). `columns` также задаёт максимум,
а число колонок автоматически уменьшается по доступной ширине и минимальной ширине карточки. DOM и
клавиатурный порядок остаются входным порядком документов; визуальная упаковка не должна менять
семантическую последовательность.

### `list`

На достаточной ширине изображение располагается слева, а заголовок и анонс справа. Для текущей темы
общая карточка использует пропорцию колонок `45/55`. При недостаточной ширине строка автоматически
становится вертикальной: изображение сверху, текст снизу. DOM сразу следует этому порядку, без
отдельной мобильной разметки и визуальной перестановки.

Брейкпоинты, минимальная ширина карточки, промежутки и доли списка являются дизайн-токенами или
правилами общей карточки, а не параметрами `MoreDocuments`.

## HTML и доступность

Секция является навигацией по связанным материалам. При `heading: on` базовая структура выглядит
так:

```html
<nav class="more-documents" aria-labelledby="more-documents-heading">
	<h2 id="more-documents-heading">Другие статьи</h2>
	<ul>
		<li><a href="/ru/articles/example/">…</a></li>
	</ul>
</nav>
```

Заголовки карточек внутри секции имеют уровень `h3`. Если `heading: off`, видимый `h2` не
рендерится, а `<nav>` получает локализованный `aria-label` из реестра типа. ID заголовка должен быть
уникальным, если страница теоретически допускает несколько таких поверхностей.

Hover, keyboard focus, цвета, рамки, тени, радиусы, типографика и интервалы берутся из общей системы
карточек. Они не настраиваются через site-config или frontmatter `MoreDocuments`.

## Валидация

Схема и build-time resolver работают fail-closed. Сборку останавливают:

- неизвестный `kind` в site-config или `docs`;
- отсутствие конфигурации текущего типа при попытке вывести секцию;
- неизвестное поле конфигурации или frontmatter;
- отсутствие обязательного поля либо условно запрещённое поле;
- неподдерживаемая связка `layout`, `columns` и `ratio`;
- `newest` у типа без даты публикации;
- неположительный или нецелый `limit`/`columns`;
- пустой или содержащий дубли ручной `docs`;
- неизвестный slug, draft, отсутствующая локаль или self-reference в `docs`;
- внешний URL вместо `{ kind, slug }`.

Пустой результат корректного `siblings` ошибкой не является: секция просто не создаётся.

## Архитектура реализации

Ответственность следует разделить на три уровня:

1. **Реестр и схемы** валидируют виды документов, конфигурацию сайта и frontmatter.
2. **Build-time resolver** выбирает документы, разрешает маршруты, анонсы и managed media и возвращает
   готовые модели карточек.
3. **Presentation-компонент** рендерит `<nav>`, заголовок и выбранную общую раскладку карточек.

Detail-страница не должна повторять выборку и сортировку отдельно для каждой локали или типа.
Существующие RU/EN article routes нужно свести к общему resolver.

Текущий `Base width="prose"` ограничивает всё содержимое страницы одним контейнером. Для
`width: wide` нужен layout-приём, при котором тело остаётся в `680px`, а послеконтентная секция
получает самостоятельный центрированный контейнер до `1200px`. Расширять всю статью ради блока
карточек нельзя.

## Критерии приёмки будущей реализации

- У статьи выводятся максимум четыре новейшие другие статьи сеткой, без анонсов.
- У тура выводятся все другие опубликованные туры алфавитным списком с анонсами.
- Generic page без ручного `docs` не получает секцию.
- Ручной список из одного документа работает без специального режима и без видимого заголовка у
  текущего `page`.
- Текущий документ никогда не попадает в собственный список.
- Пустой `siblings` не оставляет пустого заголовка или контейнера.
- RU и EN используют свои заголовки, анонсы, маршруты и алфавитный порядок без межъязыкового fallback.
- Все изображения lazy, responsive и резервируют место до загрузки.
- `grid`, `masonry` и `list` автоматически адаптируются внутри фактического контейнера.
- Навигация имеет корректное доступное имя при обоих значениях `heading`.
- Невалидные конфигурации и ручные ссылки завершают сборку понятной ошибкой.
