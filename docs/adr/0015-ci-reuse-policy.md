# ADR-0015: Повторное использование прогона PR на `main`

- **Статус:** accepted
- **Дата:** 2026-10-17
- **Связано:** ADR-0004, Story 1.8, Story 5.8

## Контекст

Джоб `reuse` в `.github/workflows/ci.yml` на push в `main` пропускает проверки, которые уже доказал
прогон PR: `pnpm check`, `migration`, e2e-джобы и Lighthouse. Сборка, `images-live`, `portfolio-live`
и деплой идут всегда. Критерий Story 1.8 при этом обещал полную проверку на `main`, а политика нигде
не была записана.

Прежняя проверка сравнивала дерево merge-коммита на `main` с деревом head PR. Но прогон PR
тестирует `refs/pull/N/merge` — слияние head с `main` на момент прогона. Если `main` после прогона
откатили или изменили, а затем смёрджили PR, дерево merge-коммита может совпасть с head, хотя прогон
тестировал другое дерево. API прогона отдаёт только head, дерево протестированного merge оно не
знает.

## Решение

Проверки на `main` пропускаются, только если успешный прогон PR тестировал ровно то дерево, которое
попало в `main`.

- Джоб `gates` прогона PR публикует пустой артефакт `tested-tree-<sha дерева>`, где дерево — это
  `git rev-parse HEAD^{tree}` протестированного merge-коммита.
- `reuse` на `main` берёт merge-коммит с двумя родителями, находит успешные прогоны PR для head из
  того же репозитория и ищет у них неистёкший артефакт с деревом текущего merge-коммита.
- Совпадение дерева head с деревом merge остаётся быстрой предпроверкой: если они различаются, база
  сдвинулась и всё запускается без запросов к артефактам.
- Любая неопределённость — squash-merge, нет успешного прогона, артефакт истёк, ошибка API — оставляет
  `verified` пустым, и запускаются все проверки.

Решение принимает `scripts/lib/ci-reuse.ts` (юнит-тест рядом), джоб `reuse` вызывает его через
`scripts/ci-reuse.ts`. Дерево включает `ci.yml` и этот скрипт, поэтому PR не может пропустить проверку, которую `main` не пропустил бы
тоже.

## Альтернативы

- Полная проверка на каждом push в `main`: надёжно, но дублирует 7–11 минут CI на каждый merge и
  не ловит ничего, что не поймал бы прогон PR того же дерева.
- Сравнивать отпечаток `dist`: совпадение `dist` не доказывает, что совпали тесты, эталоны и гейты,
  которые в `dist` не входят.
- Хранить дерево в кэше вместо артефакта: кэш PR-веток с `main` не виден.

## Последствия

Пропуск на `main` доказан деревом, а не предположением о head. Артефакт живёт 30 дней: merge старого
прогона PR без нового прогона запускает все проверки. Изменение политики reuse требует правки этого
ADR и критерия Story 1.8.
