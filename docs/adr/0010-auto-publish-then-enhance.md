# ADR-0010: Модель «auto-publish-then-enhance» и переопределённый publish gate

- **Статус:** accepted
- **Дата:** 2026-08-13

## Контекст

S10-модель публикации (см. [ADR-0009](0009-alt-caption-derivation.md) и черновой план
`docs/plans/s10-configurable-portfolio.md` в репо сайта)
рассчитана на один альбом: чтобы опубликовать фотографию, владелец вручную заполнял
`migration/data/s10-publication-input.yaml` — локализованные `title`, `description`, `colorMode`,
`publishedAt`. Это годилось для восьми фотографий `sunrises-for`, но не масштабируется на полный
корпус S6 (30 сопоставленных мастеров + 34 дополнительных). Требование «сначала напиши прозу, потом
публикуй» превращает публикацию каждой новой партии в блокирующий ручной ввод текста.

Владелец переопределил рабочий процесс (S12/1b,
`docs/plans/s12-01b-full-corpus-rescope.md` в репо сайта):

- Практика — «залил партию фотографий → она вся может быть авто-опубликована; тексты приходят
  отдельным слоем, когда угодно, без дедлайна». Публикация и авторский текст **развязаны**.
- Что действительно является намеренным актом владельца — это **активация партии образов** (запуск
  image sync + activate), а не написание описаний.

Разбор источников подтвердил и важную поправку к первоначальному брифу: у legacy-альбомов
`amazing-japan` (wp:album:55), `tuscany-in-the-mists` (wp:album:93) и `other-side-of-earth`
(wp:album:95) **нет** legacy-описаний. В `albums.jsonl` у них пустой `excerpt`, а `content` —
только gallery-шорткод; `serializeLegacyPlainText` вырезает шорткоды `[...]`, поэтому legacy-описание
для этих альбомов — пустая строка. Полагаться на «короткий EN+RU `content`» из брифа нельзя.

## Решение

**Публикация гейтится наличием активного образа + provenance активации, а не непустой прозой.
Каждое редакционное поле следует единой precedence `authored → legacy → computed`, где «optional»
означает «legacy или computed, если нет authored», а не «пусто».**

### Универсальная precedence (для каждого поля)

`authored` (owner-override) → `legacy` (если есть в выгрузке и импортировано) → `computed` fallback.
«Optional» в схеме ≠ «пусто по умолчанию»: при наличии legacy берётся legacy; computed fallback
включается, только когда нет ни authored, ни legacy.

### Переопределённый publish gate

Старый инвариант — «published требует непустой локализованной прозы (title/description/colorMode/
publishedAt)». Новый инвариант — **«published требует активного image-backed образа + provenance
активации партии»**. Это НЕ ослабляет главную гарантию: ничто не публикуется без намеренного акта
владельца. Меняется лишь определение акта: акт владельца = активация образов, а не написание текста.

### Провенанс `image-activation`

Вводится новый owner-authorized источник provenance `image-activation` в `OWNER_PROVENANCE_SOURCES`
([`migration/lib/decisions.ts`](../../migration/lib/decisions.ts)). Прежние источники
(`owner-review`, `s10-publication-input`, `s8-import`) сохраняются. Это **намеренная смена
инварианта** (флаг для аудитора): batch-publish путь принимает published-решение с provenance
активации образов вместо ручного публикационного ввода. В контракте S12/1b источник ещё не
используется ни одним решением — это подготовка контракта плана 2.

### Пер-поле источники автоматизации

| Поле                    | authored                          | legacy                                                   | computed fallback                                                                                                                   |
| ----------------------- | --------------------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `title` (photo)         | owner-override                    | legacy title                                             | — нет computed-фолбэка: если нет authored/legacy title, title не определён (display-имя падает на `caption`, `slug` — на имя файла) |
| `slug` (photo id)       | owner-approved canonical id       | —                                                        | kebab из title; если title не определён → имя файла мастера. Title из имени файла НЕ создаётся                                      |
| `description` (photo)   | owner-override                    | legacy                                                   | omit (вне publish gate)                                                                                                             |
| `colorMode`             | ручной override (тонированные ЧБ) | — (WordPress не хранит)                                  | auto из пикселей мастера (`sharp`, порог насыщенности → `black-and-white`)                                                          |
| `publishedAt`           | owner-override                    | legacy date, если есть                                   | дата активации партии образов                                                                                                       |
| `album.description`     | owner-override                    | legacy `content`/`excerpt` (у 55/93/95 пусто → fallback) | computed fallback                                                                                                                   |
| `caption` (display)     | owner-override                    | legacy                                                   | auto `Место, YYYY` (место первым, только год), билингвально                                                                         |
| `placeId`               | —                                 | —                                                        | terms/GPS ([`scripts/lib/images/gps-place.ts`](../../scripts/lib/images/gps-place.ts))                                              |
| `capturedAt`            | —                                 | —                                                        | папка архива `<YYYY>/` + EXIF `DateTimeOriginal`                                                                                    |
| `alt`                   | owner-override                    | —                                                        | [`resolvePhotoAlt`](../../src/lib/portfolio/locale.ts), fallback расширяется до `место+год` при пустом title                        |
| `tags`                  | —                                 | —                                                        | terms                                                                                                                               |
| `dominantColor`/`media` | —                                 | —                                                        | `sharp`                                                                                                                             |

`caption`-fallback билингвален «бесплатно»: место несёт EN+RU, год числовой, поэтому проверка «нет
кириллицы в EN» проходит автоматически.

`title`, `caption` и `slug` — три разных поля с разными фолбэками, их нельзя смешивать: у **title**
computed-фолбэка нет (нет authored/legacy → не определён); **`место+год` — это фолбэк `caption`** (и,
как следствие, отображаемого имени, которое при отсутствии title показывает caption); **имя файла —
фолбэк `slug`** (когда title, из которого slug выводится, не определён). Имя файла в title не
попадает. Полную read-time модель, карту отображения и **правила выведения `slug` из title**
(эвристика авто-генерации: EN-база → отбросить артикли/дубли → сохранить имена собственные → 2–3
слова → kebab/ASCII; при отсутствии title — имя файла) см.
[`docs/design/photo-text-model.md`](../design/photo-text-model.md).

### Ось видимости `unlisted`

Вводится третья независимая ось видимости `unlisted` (boolean, default = listed), ортогональная
`draft/published`. Unlisted-сущность импортируется, публикуется, встраивается в статьи/страницы, но
**не перечисляется** в portfolio-гридах и списках альбомов. Это замена legacy-тега `_private`. В
S12/1b определяется только поле схемы (без потребителя); фильтрация перечисления и маппинг
`_private → unlisted` — план 2/3.

Позже та же ось распространена на **документы** (статьи и архив курсов): у документа `unlisted` —
Tier-1 поле опорной локали (ADR-0013), поэтому оно живёт только в reference-файле пары и запрещено на
не-опорной локали. Unlisted-документ сохраняет свой маршрут (его строит `documentStaticPaths` из
полного published-набора) и остаётся встраиваемым, но выпадает из индексов статей и курсов и из
авто-списка `moreDocs` (`source: siblings`). Ручные `moreDocs`-таргеты не фильтруются: явная ссылка
владельца — это разрешённый embed, симметрично встраиванию unlisted-фото в прозу. Фильтрация вынесена в
отдельный selector (`selectListableDocuments`), а не в маршрутный загрузчик, — тот же раздвоенный
паттерн, что `getPublishedAlbums` (маршруты) против `getListableAlbums` (индекс) в portfolio-слое.

Story 5.8 расширила правило на поисковики: страница unlisted-документа, альбома или фото не попадает
в sitemap и несёт `<meta name="robots" content="noindex,follow">`. Фото наследует `unlisted` от
альбома, в контексте которого открыто. Источник — то же разбиение published/unlisted, что у контракта
редиректов (`buildRedirectRouteSets`); `check:seo-artifact` проверяет и sitemap, и мету.

## Альтернативы

- **Сохранить S10-модель «сначала проза, потом публикация»** — отвергнуто: не масштабируется на
  полный корпус, делает публикацию каждой партии заложником ручного ввода текста без выигрыша в
  качестве (описания можно дописать позже как отдельный слой).
- **Считать `album.description` всегда авторским обязательным полем** — отвергнуто: у трёх новых
  альбомов legacy-описаний нет, обязательность заблокировала бы их публикацию на несуществующем
  тексте.
- **Оставить `_private` тегом** — отвергнуто: видимость — независимая ось, а не таксономический тег;
  отдельное поле `unlisted` не смешивает listing-политику с семантикой тегов.

## Последствия

- (+) Партия образов публикуется сразу после активации; авторский текст — поздний decoupled слой без
  дедлайна.
- (+) Владелец авторит только осмысленный текст; технические и выводимые поля заполняются
  автоматически с проверяемой precedence.
- (+) Главная гарантия сохранена: без намеренного акта владельца (активация образов) ничто не
  публикуется.
- (−) Отображаемое имя без authored/legacy title падает на `caption` (его цепочка `authored → legacy
→ computed «Место, YYYY»` — в таблице выше), что беднее авторского названия — приемлемо,
  всегда можно переопределить authored-title. (У самого поля `title` computed-фолбэка нет.)
- (−) Осознанная смена инварианта provenance (акт владельца = активация, а не текст) — зафиксирована
  здесь как контракт для downstream-планов; аудитор должен трактовать `image-activation` как
  легитимный owner-источник.
- Исполнение: релаксация схемы `title`/`description`, auto-детекция `colorMode`, `publishedAt =
activation date`, переопределение `runPublishGate` и read-time precedence-резолвер — планы 2/3;
  пиксельная детекция и семантика даты активации — план 5. В S12/1b исполняются только
  fixture-безопасные изменения (см. рескоуп-план).
