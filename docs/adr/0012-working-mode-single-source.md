# ADR-0012: После миграции — единый редактируемый источник, миграционные леса снимаются

- **Статус:** accepted
- **Дата:** 2026-08-26
- **Уточняет:** [ADR-0011](0011-legacy-corpus-errata.md) (errata-петля остаётся в силе на время миграции; этот ADR задаёт steady-state после неё)

## Контекст

ADR-0011 объявил normalized JSONL (`migration/data/legacy/normalized/*.jsonl`) каноническим **редактируемым**
источником, а WordPress-дамп — только bootstrap. Формально править исходник можно. Но на практике
вокруг любой правки выросла двухслойная схема с криптографическим забором между слоями:

```
JSONL (объявлен источником)  ──импортёр──▶  src/content/** (генерат)
        ▲                                          ▲
   машинный ноднострочный                   drift-гейт байт-в-байт
   блоб — править неудобно                  сверяет с генератом → править ЗАПРЕЩЕНО
```

К этому добавлены два sha256-дайджеста (translation `sanitizedSourceDigest`, factcheck
`factcheckSourceDigest` — тогда по legacy JSONL; с Story 2.1 он считается по RU-документу
`src/content`, см. ADR-0011), always-on drift-гейты (`content:import:full:check`, `content:translations:check`)
и errata-журнал. В результате удобного места для авторской правки нет **ни на одном слое**: генерат
трогать нельзя (забор), а источник — это машинный дамп. Чтобы добавить один абзац, автор обязан
пройти цепочку «правка JSONL → запись в errata → обновить два дайджеста → перегенерировать пакеты →
пересобрать `src/content` → возможно переперевести EN → зелёные гейты». Для сайта из ~18 статей это
тупик: данные фактически невозможно редактировать удобно.

Эта строгость оправдана **на время миграции** (S6–S12): доказать, что импорт из WordPress ничего не
потерял и воспроизводим, отследить владение изображениями, управлять провенансом переводов при
массовом переносе. Но это строительные леса переноса. Ошибка — оставить их в режиме авторства:
строгость времени миграции застыла и превратилась в модель времени авторства.

Ключевое разграничение, которое ADR-0011 смешал: **миграция занимается только переносом**. Всё
последующее — опечатки, новые абзацы, фактчек-исправления, авторские end-note — это работа уже с
**рабочим сайтом**, а не с миграционным артефактом.

## Решение

Явно разделяем два режима жизни контента.

**Миграционный режим (S6–S12) — без изменений.** JSONL канон, drift-гейты, дайджесты, errata-петля
(ADR-0011) действуют, пока перенос не доказан завершённым. Их задача — не потерять данные при
массовом импорте.

**Рабочий режим (после завершения переноса, этап S13).** Сайт «выпускается» из миграции:

1. **Источник истины — один редактируемый слой** (Markdown / Astro content collections), а не пара
   «JSONL → генерат». То, что автор редактирует, и есть контент.
2. **Байтовый drift-забор `content:import:*` снимается** (или становится dev-only diagnostics, не
   always-on CI-гейтом). Генерат перестаёт быть «чистой функцией» второго слоя, потому что второго
   слоя больше нет.
3. **Двуязычие — мягкий сигнал, а не стена.** Жёсткий `sourceDigest`-гейт заменяется durable-маркером
   `translatedFromDigest` (sha256 канонического RU-body на момент перевода) и **служебной страницей
   `/status/`**, а не пометкой внутри материала: текст статей/страниц/курсов для посетителя не меняется.
   Маркер информирует автора, но не роняет сборку.
4. **errata — необязательный журнал** (провенанс по желанию), а не обязательный обряд перед каждой
   правкой.
5. **Любая правка текста** — опечатка, новый абзац, замена ссылки, фактчек-фикс, end-note — делается
   как обычное редактирование одного файла контента. Никаких дайджестов, пересборки и журналов на
   пути.
6. **WordPress-дамп и normalized JSONL остаются историческим артефактом переноса**, не живым
   источником. Повторный импорт — только осознанный ре-bootstrap (guard ADR-0011 сохраняется).

Переход исполняется как отдельный этап роадмапа (S13), до его завершения действует ADR-0011.

**Служебная страница `/status/` (S13).** Публичный по прямому URL, но ненавигационный
(`noindex,follow`, вне sitemap, без ссылок в UI) статический срез. Семантика:

- **Только статический снимок.** Данные строятся в build-time из Content Collections и tracked JSON
  (`src/generated/images-release.json`); никакой сети, секретов, mtime, Git или живого R2. UTC-время
  внизу обозначает **момент генерации снимка**, а не дату изменения контента, deploy или health CDN.
- **Tracked descriptor ≠ live verification.** Image-панель говорит «active tracked descriptor» и число
  ассетов манифеста, но не заявляет, что R2/CDN проверены сейчас — живое доказательство остаётся
  CI-only (`check:images-live`).
- **Жизненный цикл маркера.** `translatedFromDigest` пишет единственная команда
  `content:translation-marker:confirm --document <collection>/<key> --write`: её вызывают
  `/translate` после записи перевода и `/validate` после явного подтверждения владельцем вручную
  проверенной пары. Руками маркер не правится; одноразовый baseline-бэкфилл S13 (`stamp`) удалён. Обычная правка RU не обновляет маркер —
  расхождение и есть честный сигнал. Отсутствующий или расходящийся
  корректный маркер = `needs review`; некорректный (не 64-hex) остаётся schema-ошибкой
  `content:validate`, а не runtime-fallback. `content:translation-marker:check` — advisory, вне
  `pnpm check`.

## Альтернативы

- **Оставить двухслойную схему с забором навсегда** — отвергнуто: делает авторство невыносимым,
  удобного места для правки нет ни на одном слое; именно эту боль ADR и устраняет.
- **Начать править `src/content` напрямую уже сейчас** — отвергнуто: пока S12 не закрыт, drift-гейт
  ещё ловит реальные потери массового импорта. Леса снимаем только когда перенос доказан
  завершённым, не посреди него.
- **Overlay-слой правок поверх JSONL** — отвергнуто по той же причине, что и в ADR-0011: overlay
  поверх source-of-truth раздваивает источник смысла.
- **Держать жёсткий двуязычный дайджест-гейт и в рабочем режиме** — отвергнуто: sha256-стена в CI
  ради инварианта «EN мог устареть» несоразмерна; мягкого видимого флага достаточно, а цена ошибки
  (устаревший перевод) низка и обратима.

## Последствия

- (+) Правка контента = редактирование одного файла. Добавить абзац, поправить опечатку, заменить
  ссылку — без дайджестов, пересборки и журнала.
- (+) Скиллы `/factcheck`, `/factcheck-apply`, `/fixcontent` и `/translate` радикально упрощаются:
  применение фикса становится обычной правкой файла, фактчек лишь предлагает список замечаний, перевод
  не проходит sha-гейты. Избыточная сложность, накопленная под миграционный забор, снимается.
  Окончательная судьба каждого скилла (упростить, слить с другим или отказаться) решается в момент их
  переработки в S13, а не здесь: этот ADR фиксирует направление (снять забор), а не отмену скиллов.
- (+) Честная ментальная модель: миграция переносит; всё остальное — на рабочем сайте.
- (−) Теряем криптографическую гарантию «генерат = функция источника» — осознанная цена: после
  миграции источник и есть контент, дублировать и сверять нечего.
- (−) Двуязычная свежесть становится дисциплиной автора плюс мягкий сигнал, а не CI-гейт; риск
  «забыл обновить EN» купируется видимой пометкой, а не блокировкой.
- Порядок: ADR-0011 в силе во время миграции (до конца S13-перехода); ADR-0012 — steady-state после.
