# ADR-0013: Опорная локаль как единый источник document-level frontmatter

- **Статус:** accepted
- **Дата:** 2026-09-09
- **Уточняет:** [ADR-0012](0012-working-mode-single-source.md) (рабочий режим: контент правится как один
  файл; этот ADR убирает дубли document-level полей внутри пары локалей)

## Контекст

Парные RU/EN документы (коллекции `articles`, `pages`) дублировали несколько document-level полей в
обоих файлах локали и держались за счёт проверки равенства «оба должны совпадать»:

- `integrity.ts` (`checkDocumentPairs`) сверял `slug`, `status`, `publishedAt`, `kind`, `source`
  между двумя файлами локали и поднимал `locale-mismatch` при расхождении.
- Обложка документа жила **вне** документа — в центральном конфиге `banners.documents`
  (`translationKey → photoId`), то есть была третьим источником правды, отдельным от frontmatter.
- Опорная локаль, из которой читаются «одно значение на пару» поля, была захардкожена:
  `const REFERENCE_LOCALE: Locale = 'en'` в `documents.ts`.

Из-за этого приходилось редактировать два файла в lock-step на каждое общее поле; обложка была
третьим источником правды в глобальной карте по `translationKey`; а опорная локаль была прибита к
`en`, что неверно для RU-авторского сайта и не обобщается на будущий EN-only сателлит.

## Решение

Вводим конфигурируемую **опорную локаль** `content.referenceLocale` (здесь `ru`) и делаем файл опорной
локали единственным источником фиксированного набора **Tier-1** document-level полей.

- **Tier-1 набор:** `coverId`, `publishedAt`, `legacyId`, `kind`. Эти поля хранятся ТОЛЬКО в файле
  опорной локали и **запрещены** в другой локали; их cross-locale равенство снято. Позже (S14/01 P11)
  набор расширен полем `courseStatus` (`archive | current`) — статусом курса, который сопровождает
  `kind: course`.
- **Плоский `legacyId`.** Провенанс мигрированного контента раньше был вложенным объектом
  `source: { legacyId: … }` (union с `source: { sha256, master }` для новых мастеров). Ради простоты
  frontmatter вложенность снята: идентичность теперь — плоские поля верхнего уровня `legacyId` **либо**
  `sha256`+`master` (взаимоисключение и парность проверяет `refineSourceIdentity` в `schemas.ts`).
  Tier-1-ось не изменилась — переименовано лишь имя поля (`source` → `legacyId`).
- `coverId` — первый экземпляр общего правила: обложка переезжает из конфига (`banners.documents`) в
  сам документ. `banners.documents` удаляется, `banners.surfaces` (индексы разделов + contacts)
  остаётся. Ради единообразия альбомное поле `coverPhotoId` тоже переименовано в `coverId`.
- **`slug` и `status` осознанно остаются парными** — их равенство по-прежнему проверяется integrity.
  Дедуп `slug`/`status` — вне объёма этого раунда: `status` завязан на модель публикации (ADR-0012) и
  читается в ~40 местах, а `slug` держит гибкость локализованных URL.
- Правило Tier-1 сформулировано как «запрещено на локали ≠ опорной», поэтому оно не конфликтует с
  будущим EN-only сайтом: одна локаль — пар нет — «forbidden on non-reference» просто не срабатывает.
  С истории 4.2 набор локалей берётся из `content.locales` в `site.yaml`: `documents.ts`,
  `status/build-data.ts` и `integrity.ts` получают список активных локалей из конфига, а `locale-gap`
  требует у published-документа все активные локали. С истории 6.10a короткие локализованные поля
  альбомов, фото, таксономии и `featured/home.yaml` — записи ровно по активным локалям.
- `translatedFromDigest` (история 4.2) запрещён на опорной локали и допустим только на переводах;
  правило проверяет `integrity.ts` относительно `content.referenceLocale` (код `reference-marker`), а не
  схема по литералу `en`.

## Альтернативы (отвергнуто)

- **«Оба равны» (текущая схема)** — сохраняет дубли и lock-step-редактирование двух файлов; ровно ту
  боль ADR и устраняет.
- **«Читать любую локаль»** — недетерминированно, скрывает дрейф между файлами; опорная локаль делает
  источник явным.
- **«Держать обложку в конфиге»** — третий источник правды и ручной прогон импортёра ради одного
  редакционного решения; обложка переезжает в документ.
- **«Дедупить `slug`/`status` сейчас»** — `status` завязан на модель публикации/ADR-0012 и читается в
  ~40 местах; `slug` держит гибкость локализованных URL. Осознанно отложено.

## Последствия

- (+) Одна точка редактирования Tier-1 полей: правится только файл опорной локали.
- (+) Обложка документа — свойство документа, а не отдельная конфиг-карта; второго источника правды про
  медиа не остаётся.
- (−) Резолверы обязаны читать `kind`/`publishedAt`/`coverId` через опорную запись: EN-чтение теперь
  даёт `undefined`, а фильтр семейства (`isCourse`/`isGenericPage`) должен применяться к опорной
  записи группы, иначе не-опорный файл теряется и `resolvePair` падает «missing locale».
- (−) Проверка media-роли обложки переезжает из обхода конфиг-карты в обход опубликованных документов с
  `coverId`; корпусный strip не-опорных файлов; правка эмита импортёра (Tier-1 только в опорный файл).
- Будущий EN-only сайт валиден без правки правила Tier-1 (одна локаль — правило не срабатывает).
