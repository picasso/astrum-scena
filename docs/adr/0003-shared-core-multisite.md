# ADR-0003: Общее Astro-ядро для трёх сайтов

- **Статус:** accepted
- **Дата:** 2026-07-18

## Контекст

Мигрируется не один сайт, а три похожих WordPress-сайта (разный дизайн и направление, но общая
идея: редко обновляемый контент-сайт, WordPress избыточен). Нужно не мигрировать трижды с нуля,
а выделить переиспользуемые паттерны.

## Решение

Строим **переиспользуемый «migration kit»** и применяем трижды. Три слоя:

1. **Playbook** — воспроизводимый пошаговый процесс миграции (пишется на сайте №1, дальше — чеклист).
2. **Общее Astro-ядро** — базовые компоненты и инфраструктура: hero-слайдер, галерея,
   PhotoSwipe-остров, i18n, пайплайн водяного знака, Telegram-функция, конфиги тулчейна
   (Prettier/ESLint/TS/Vitest/CI). Каждый сайт наследует ядро и накладывает свою тему
   (цвета, типографика, направление).
3. **Custom skill `wp-to-astro`** — упаковка процесса в вызываемый навык.

Сайт №1 выступает как R&D — на нём окупаются вложения в структуру для №2 и №3.

## Альтернативы

- **Мигрировать каждый сайт независимо** — отвергнуто: тройная работа, расхождение решений.
- **Монорепозиторий на все три сайта** — отложено: решим после сайта №1, когда станет ясно,
  сколько кода реально общего. Пока — общее ядро как переиспользуемая основа/шаблон.

## Последствия

- (+) Сайты №2 и №3 запускаются по накатанной, дёшево.
- (+) Единые тулчейн и процесс на всех сайтах.
- (−) Вложение в обобщение на сайте №1 (осознанно, окупается дальше).
- Открытый вопрос: монорепо vs отдельные репозитории с общим шаблоном — решаем позже.
