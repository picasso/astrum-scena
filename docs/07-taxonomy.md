# Новая таксономия фотографий

Канонический контракт S7 для структуры портфолио. Он фиксирует смысл сущностей и полей до
реализации Zod-схем и импорта на S8. Исходные данные и правила переноса legacy-значений описаны в
карте миграции S7 (репо сайта), архитектурное решение — в
[ADR-0007](adr/0007-photo-taxonomy.md).

## Цели

- Дать посетителю два понятных способа входа в портфолио: авторские серии и географические
  подборки.
- Разрешить одной фотографии участвовать в нескольких альбомах и динамических срезах без
  дублирования файла или метаданных.
- Отделить редакционные решения владельца от объективных метаданных и поисковых признаков.
- Задать стабильные идентификаторы и контролируемые значения, пригодные для Zod-схем и
  воспроизводимого импорта.

## Иерархия портфолио

```text
Portfolio
├── Series / Серии
│   └── Album / Альбом
└── Places / Места
    └── Album / Альбом
```

Верхний уровень содержит ровно две категории:

| ID       | EN label | RU label | Назначение                                                  |
| -------- | -------- | -------- | ----------------------------------------------------------- |
| `series` | Series   | Серии    | Авторские проекты, объединённые идеей или визуальным языком |
| `places` | Places   | Места    | Подборки, где главным объединяющим признаком служит место   |

Альбом принадлежит ровно одной категории. Фотография может входить в ноль, один или несколько
альбомов через ссылки из альбомов. Нулевая принадлежность допустима для нового или служебного
контента до кураторской раскладки, но такая фотография не появляется в основной навигации
портфолио.

Альбом — редакционная сущность: у него есть стабильный ID, локализованные название и описание,
`coverId` и упорядоченный массив `photoIds`. `coverId` обязателен и должен присутствовать
в `photoIds`. `photoIds` — единственный канонический источник принадлежности и порядка. Обратный
массив `photo.albumIds`, если он нужен приложению, вычисляется из альбомов и не редактируется
отдельно. Фотография хранится один раз; порядок внутри разных альбомов может различаться.

## Динамические срезы

Динамический срез вычисляется из метаданных фотографий и не является категорией или альбомом.
Ссылки на фотографии остаются каноническими, а создание среза не копирует контент.

### Recent Works

`Recent Works` / «Недавно добавленные» строится из фотографий со `status: published` сортировкой
по `publishedAt` от новых к старым. Количество элементов задаётся конфигурацией представления, а
не метаданными фотографии. Legacy-тег `recent` не переносится.

`publishedAt` означает дату появления фотографии на новом сайте. Это не дата съёмки и не дата
legacy-вложения WordPress.

### Favorites

`Favorites` / «Избранное» строится только из фотографий со `status: published` и редакционным
признаком `favorite: true`.

- Тип поля — boolean, значение по умолчанию — `false`.
- Признак назначает и снимает только владелец сайта или действующий от его имени явный
  редакционный процесс.
- `favorite` не выводится из рейтинга, количества просмотров, legacy-тегов, альбомов или других
  косвенных сигналов.
- Порядок среза по умолчанию — `publishedAt` от новых к старым; отдельный ручной порядок можно
  добавить позднее как самостоятельное решение.

## Состояние публикации

Сохраняемое поле `status` имеет два значения:

- `draft` — фотография может быть неполной и не попадает в публичные маршруты или динамические
  срезы;
- `published` — фотография доступна публично и обязана иметь `publishedAt` и `colorMode`.

Наличие `publishedAt` само по себе не заменяет `status`. Это исключает неявные различия между
импортёром, коллекциями и построением динамических срезов.

## Сохраняемые метаданные фотографии

Следующий логический контракт должен быть выражен Zod-схемой на S8. Здесь указаны смысл,
обязательность и источники, а не синтаксис конкретной реализации.

| Поле          | Тип                              | Обязательность    | Правило                                                                                  |
| ------------- | -------------------------------- | ----------------- | ---------------------------------------------------------------------------------------- |
| `id`          | stable kebab-case ID             | да                | Не зависит от языка и не меняется вместе с заголовком                                    |
| `title`       | `{ <locale> }`                   | да                | Каждая локаль `content.locales`; техническое имя файла не считается финальным заголовком |
| `status`      | `draft` / `published`            | да                | Единственный источник публичного состояния                                               |
| `placeId`     | stable place ID                  | нет               | Ссылка на самое точное подтверждённое место                                              |
| `capturedAt`  | частичная дата `YYYY \| YYYY-MM` | нет               | Только подтверждённая дата съёмки; без дня/времени/timezone                              |
| `publishedAt` | ISO date or datetime             | да для публикации | Дата появления на новом сайте                                                            |
| `colorMode`   | `color` / `black-and-white`      | да для публикации | Явный визуальный признак, не цветовая палитра                                            |
| `favorite`    | boolean                          | да                | Редакторский признак, по умолчанию `false`                                               |
| `tags`        | unique controlled tag IDs        | да                | Может быть пустым; только значения из словаря                                            |

Если дата съёмки неизвестна, `capturedAt` остаётся пустым. EXIF на S9 может предложить значение, но
не должен перезаписывать подтверждённые редакционные данные без проверки.

`capturedAt` хранит строго `YYYY` либо `YYYY-MM` (отдельная `partialCapturedAtSchema`, календарная
валидация месяца `01..12`). Год — источник истины из подтверждённой годовой папки канонического
архива, а не из EXIF; месяц добавляется только при совпадении EXIF-года с folder-year. День, время и
timezone не хранятся, и месяц не становится отдельным taxonomy-тегом. Контракт `publishedAt` при этом
не меняется и продолжает требовать полную дату.

### GPS → placeId: предложение только для review

EXIF GPS извлекается из мастера исключительно как приватный вход и никогда не попадает в
content/manifest/derivatives. Отдельный build-time `config/place-gps-bounds.yaml` задаёт согласованные
грубые bounding box'ы, keyed только существующими controlled `placeId`. По точке предлагается наиболее
конкретный однозначный существующий `placeId`, чья зона её содержит (вложенные зоны — «глубже
выигрывает»). Отсутствие совпадения, несвязанное перекрытие, равная specificity или конфликт с уже
утверждённым `placeId` дают review-item, а не автоматическое применение. Пайплайн никогда не создаёт
новые места и не применяет предложение без отдельного согласования владельцем.

## Вычисляемые поля фотографии

Вычисляемые поля не входят в сохраняемую запись Content Collection и не редактируются:

| Поле       | Источник                                              |
| ---------- | ----------------------------------------------------- |
| `year`     | Четырёхзначный год из подтверждённого `capturedAt`    |
| `albumIds` | Обратный индекс по всем каноническим `album.photoIds` |

## Места

Место — отдельная справочная сущность, а не свободный тег. Фотография ссылается на самое точное
известное место, а родительские уровни получаются обходом иерархии:

```text
country → region → locality
```

Не все три уровня обязательны. Например:

- `italy → tuscany`;
- `italy → venice`;
- `namibia → skeleton-coast`;
- `new-zealand → moeraki-boulders`;
- `united-states → monument-valley`.

Континенты не входят в обязательную иерархию: они слишком широки для текущего портфолио и при
необходимости могут быть вычислены из страны. У места есть стабильный ASCII kebab-case ID и
названия по локалям `content.locales`.

Одна фотография имеет не более одного `placeId`: физическая точка съёмки одна. Альбом категории
`places` может включать несколько близких мест, если это соответствует его редакционной теме.

## Контролируемые теги

Тег описывает подтверждённый посетителю понятный признак и не заменяет место, альбом, год,
`colorMode`, `favorite` или дату публикации. На старте утверждён следующий словарь:

| Kind        | ID              | EN label           | RU label         |
| ----------- | --------------- | ------------------ | ---------------- |
| `subject`   | `canyons`       | Canyons            | Каньоны          |
| `subject`   | `carnival`      | Carnival           | Карнавал         |
| `subject`   | `clouds`        | Clouds             | Облака           |
| `subject`   | `dunes`         | Dunes              | Дюны             |
| `subject`   | `fields`        | Fields             | Поля             |
| `subject`   | `fumarole`      | Fumarole           | Фумарола         |
| `subject`   | `gondola`       | Gondola            | Гондола          |
| `subject`   | `ice`           | Ice                | Лёд              |
| `subject`   | `seascape`      | Seascape           | Морской пейзаж   |
| `subject`   | `trees`         | Trees              | Деревья          |
| `condition` | `fog`           | Fog                | Туман            |
| `condition` | `rays`          | Rays               | Лучи             |
| `condition` | `winter`        | Winter             | Зима             |
| `motif`     | `reflection`    | Reflection         | Отражение        |
| `motif`     | `shadows`       | Shadows            | Тени             |
| `motif`     | `silhouette`    | Silhouette         | Силуэт           |
| `moment`    | `sunrise`       | Sunrise            | Рассвет          |
| `moment`    | `sunset`        | Sunset             | Закат            |
| `technique` | `aerial`        | Aerial photography | Аэросъёмка       |
| `technique` | `long-exposure` | Long exposure      | Длинная выдержка |

Новый тег добавляется только если:

1. его смысл нельзя выразить существующим структурным полем;
2. он понятен посетителю без знания внутренней организации архива;
3. он подтверждён хотя бы одной фотографией;
4. для него заданы стабильный ID и локализованные названия;
5. его предполагается использовать для поиска, фильтра или связанного контента.

`aerial` и `canyons` утверждены владельцем для значимого будущего корпуса, хотя в текущем
портфельном subset S6 к фотографиям не привязаны. Это допустимое исключение из требования № 3:
теги входят в словарь, но не назначаются текущим фотографиям автоматически.

Цветовые legacy-теги (`red`, `orange`, `pink`, `green`, `blue`, `violet`) не переносятся: они
субъективны, плохо масштабируются и не заменяют `colorMode`. Географические дубли в `post_tag`
переносятся в `placeId`. Опечатки и служебные значения удаляются.

## Именование

- Все ID и slug — lowercase ASCII kebab-case.
- ID стабилен и не меняется при исправлении или переводе отображаемого названия.
- Отображаемые названия хранятся записью по локалям `content.locales`; язык URL определяется маршрутом, а не ID.
- Альбомные ID описывают содержание, а не WordPress ID и не положение в меню.
- Единственное и множественное число UI-подписей живёт в i18n-словарях, не в контентных ID.
- Значения массивов уникальны; порядок `tags` семантики не несёт.

## Пограничные случаи

- Фотография в нескольких альбомах хранится одной сущностью; канонические `album.photoIds`
  содержат ссылки, а обратная принадлежность вычисляется.
- Альбом, сочетающий место и авторскую концепцию, классифицируется по главному редакционному
  замыслу. Поэтому `Tuscany in the Mists` относится к `series`, несмотря на географическое
  название.
- `Recent Works` и `Favorites` не могут вручную получать собственные списки фотографий.
- Фотография со `status: draft` может не иметь альбома, места, даты и `colorMode`, но не
  публикуется в маршрутах или динамических срезах до редакционной проверки.
- Неподтверждённые данные не угадываются по имени файла. Они остаются пустыми и попадают в отчёт
  импорта.
- Служебные изображения, портреты автора и иллюстрации статей не попадают в фототаксономию только
  потому, что являются WordPress-вложениями.
- Удаление тега из словаря требует сначала удалить или заменить все ссылки на него.
