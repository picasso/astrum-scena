# Вводный курс: что такое Astro

Короткое введение для тех, кто знает Next/React, но не работал с Astro.
Написано с опорой на модель RSC и `'use client'`.

## Короткий ответ

**Astro — это фреймворк** (не библиотека), того же класса, что Next.js — «мета-фреймворк» для
сборки сайтов, построенный на Vite. Но философия по умолчанию другая:

> **Next — фреймворк для приложений. Astro — фреймворк для контента.**

Next по умолчанию грузит в браузер React-рантайм и гидратирует страницу. Astro по умолчанию
отдаёт **чистый HTML и ноль JavaScript**, а интерактив добавляется точечно.

## Главная идея — в терминах RSC и островов

- **`.astro`-компонент ≈ React Server Component**, который **никогда не гидратируется**.
  Выполняется на сборке, рендерится в HTML, в браузер ничего не тащит.
- **«Остров» ≈ компонент с `'use client'`.** Кусочек, которому нужен JS (лайтбокс, слайдер).
  Помечается явно — гидратируется только он, своим маленьким бандлом, независимо от остального.

Отсюда **islands architecture** — «острова интерактивности в море статичного HTML».
Инверсия дефолта: в Next «всё клиентское, отключай где не надо»; в Astro «всё статичное,
включай интерактив где надо».

## Анатомия `.astro`-компонента

```astro
---
// Component Script — выполняется на СБОРКЕ, в браузер не попадает.
// По сути тело RSC: top-level await, чтение файлов, доступ к данным.
import Layout from '../layouts/Layout.astro'
import { getCollection } from 'astro:content'

const albums = await getCollection('albums') // как data-fetch в RSC, без getStaticProps
---

<!-- Ниже — шаблон. JSX-подобный, но HTML-first. -->
<Layout>
	<h1>Portfolio</h1>
	<ul>
		{albums.map((album) => <li>{album.data.title.ru}</li>)}
	</ul>
</Layout>
```

Часть между `---` — «скрипт компонента» (аналог серверного тела). Ниже — разметка.
Всё превращается в HTML на сборке. JS отсюда не уезжает.

## Острова

```astro
---
import PhotoViewer from '../components/PhotoViewer.tsx' // обычный React-компонент
---

<!-- без client:* — статичный HTML, ноль JS --><!-- с client:* — гидратируется как остров -->
<PhotoViewer client:visible photos={photos} />
```

Директивы `client:*` — когда включать JS:

- `client:load` — сразу (≈ обычный `'use client'`).
- `client:visible` — когда доскроллил (идеально для галерей ниже сгиба).
- `client:idle` — когда браузер освободился.

React-компоненты работают (shadcn-обёртки тоже) — просто как острова.

## Astro vs Next — по пунктам

|                                 | Astro                                   | Next.js                              |
| ------------------------------- | --------------------------------------- | ------------------------------------ |
| Класс                           | фреймворк (на Vite)                     | фреймворк                            |
| Вывод по умолчанию              | статичный HTML, **ноль JS**             | React-приложение, JS-рантайм всегда  |
| Модель компонента               | `.astro` (только сервер) + острова      | RSC + client components              |
| UI-фреймворки                   | React/Vue/Svelte/Solid — можно микс     | только React                         |
| Роутинг                         | файловый, `src/pages/`                  | файловый, `app/`                     |
| Данные                          | top-level await в скрипте               | RSC / fetch / server components      |
| Клиентское состояние (Effector) | только внутри острова, не сквозное      | на всё приложение                    |
| Силён в                         | контент: галереи, блоги, доки, лендинги | приложения: дашборды, auth, realtime |

## Что остаётся из мира Next/React, а что уходит

**Остаётся:** TypeScript, Tailwind v4, React-компоненты (как острова), Vite, ESLint/Prettier,
файловый роутинг, JSX-подобный синтаксис, интуиция Server Components.

**Уходит / не нужно:** сквозное клиентское состояние (Effector между страницами — острова
изолированы), церемония RSC-загрузки данных, `next/image` (у нас свой пайплайн),
хуки/`useEffect` живут только внутри островов.

## Когда что

- **Astro** — когда сайт это преимущественно **контент**: показать, прочитать, посмотреть.
  SEO и скорость важны, интерактива мало. → Фотосайт.
- **Next** — когда это **приложение**: сложный клиентский стейт, авторизация, реактивные
  дашборды, realtime. → durer-ai, neuro-hub.

Тот же человек, разные инструменты под разные задачи.

## Одной фразой

**`.astro`-компонент — это Server Component, который отказывается гидратироваться, пока ты его
об этом явно не попросишь (островом).**
