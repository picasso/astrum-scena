# BK17. Источники классов Tailwind

**Статус:** сделано · 2026-10-25, история 6.1b
([спек](../../_bmad-output/implementation-artifacts/spec-6-1b-tailwind-source-boundary.md))

## Зачем

Правка документа или технического спека не должна менять CSS сайта.

## Что сейчас

`src/styles/global.css` подключает Tailwind с `source(none)` и явными `@source`: весь `src/` без
`src/content`. Документы, спеки, скрипты и тексты статей на CSS не влияют, а `content:validate`
запрещает атрибут `class` в контенте. Правило, класс-метка, список исчезнувших правил и новый бюджет —
в базовом объёме CSS сайта (`css-baseline.md`, репо сайта).

До этого Tailwind сканировал весь репо: в истории 5.10 имя утилиты в технической заметке меняло
fingerprint сборки, в PR #65 строка `tracking-[0.42em]` из ADR-0016 уронила `check:page-budget`.

## Когда вернуться

В 6.2 — `@source` пакета ядра и демо; граница сайта уже задана.

## Что сделать и что не входит

Явно задать источники Tailwind и защитить регрессиями: изменение только документа не меняет вывод CSS,
нужный класс из допустимого источника появляется. Удаление нужных классов или ослабление бюджетов не
входит; CSS пакета ядра и демо — 6.2.

## Готово, когда

Источник классов ограничен и документирован; обе регрессии входят в check или CI, production
сборка и бюджеты проходят, визуальный результат принят без скрытой потери стилей.
