# Wrap Around

- **Статус контракта:** согласован
- **Обновлено:** 2026-09-25
- **Общие правила:** [контентные блоки](README.md)

## Назначение

`Wrap Around` показывает одно или несколько изображений слева или справа от текста. На достаточно
широком контейнере последующий текст обтекает блок. Когда для текста и изображения уже не хватает
места, блок становится полноширинным и обтекание отключается.

Основной визуальный пример — первый абзац страницы About исходного сайта,
где фотография расположена справа. Пример подтверждает назначение, но не является источником API:
параметры берутся из актуального Gutenberg-блока `zu/wrap-around` и уточняются решениями ниже.

Блок не предназначен для:

- центрированного одиночного изображения без обтекания;
- больших коллекций и сложных раскладок — для них нужен отдельный `Gallery`;
- произвольной HTML/CSS-композиции внутри контента;
- загрузки изображений по внешнему URL.

## Публичный контракт

```ts
type WrapPosition = 'left' | 'right'
type WrapGap = 'none' | 'tiny' | 'small' | 'medium' | 'large'
type ImageFrame = 'none' | 'thin' | 'medium' | 'thick'
type ImageFrameColor = 'default' | 'alt'
type LightboxScope = 'block' | 'page'

type ImageAction =
	| 'none'
	| 'lightbox'
	| 'photo'
	| { type: 'album'; albumId: string }
	| { type: 'custom'; href: string; newTab?: boolean }

type WrapAroundImage = {
	imageId: string
	alt?: string
	caption?: string | false
	action?: ImageAction
}

type WrapAroundOptions = {
	position?: WrapPosition
	width?: number
	outside?: number
	textGap?: WrapGap
	imageGap?: WrapGap
	frame?: ImageFrame
	frameColor?: ImageFrameColor
	action?: ImageAction
	inlineCaption?: boolean
	lightboxCaption?: boolean
	lightboxScope?: LightboxScope
}

type WrapAroundProps = WrapAroundOptions &
	({ imageId: string; images?: never } | { images: WrapAroundImage[]; imageId?: never })
```

Нужно передать ровно один источник: простой `imageId` или расширенный `images`. `imageId`
нормализуется в один элемент с настройками изображения по умолчанию; параметры уровня блока
(`position`, `width`, `action` и остальные) доступны в обеих формах. Несколько изображений и
индивидуальные `alt`/`caption`/`action` overrides доступны только через `images`. Отдельного
`multipleImages` нет: режим однозначно следует из количества элементов после нормализации.

| Параметр          | Default      | Правило                                                                  |
| ----------------- | ------------ | ------------------------------------------------------------------------ |
| `imageId`         | —            | Простой одиночный источник без индивидуальных overrides                  |
| `images`          | —            | Расширенный непустой массив; рекомендуемое количество — 1–4              |
| `position`        | `'left'`     | Сторона float-композиции: `'left'` или `'right'`                         |
| `width`           | auto         | Целый процент `20..80`; отсутствие включает автоматический подбор        |
| `outside`         | `0`          | Доля ширины `0..60`, выходящая за внешнюю границу prose                  |
| `textGap`         | `'small'`    | Расстояние между группой изображений и обтекающим текстом                |
| `imageGap`        | `'small'`    | Вертикальное расстояние между изображениями группы                       |
| `frame`           | `'thick'`    | Рамка каждого изображения: `none`, `thin`, `medium` или `thick`          |
| `frameColor`      | `'default'`  | Цвет рамки: сайт-токен `default` или `alt`; при `frame='none'` не влияет |
| `action`          | `'lightbox'` | Общее действие блока; отдельное изображение может его переопределить     |
| `inlineCaption`   | `false`      | Показывать разрешённую подпись под каждым изображением                   |
| `lightboxCaption` | `true`       | Передавать разрешённую подпись в lightbox                                |
| `lightboxScope`   | `'page'`     | Общая совместимая группа страницы или изолированная группа блока         |

Произвольный `className`, внешний `src`, готовые `srcset`/`sizes`, размеры файла и legacy-поля
`alink`, `csswidth`, `rsjs` в публичный контракт не входят.

## Примеры авторинга

Минимальный вариант использует автоматическую ширину и все defaults:

```mdx
<WrapAround imageId="dr-bhutan" />
```

Параметры блока остаются доступны и в короткой форме:

```mdx
<WrapAround imageId="dr-bhutan" position="right" action="none" />
```

Выход изображения за внешнюю границу prose при сохранении его визуальной ширины:

```mdx
<WrapAround imageId="dr-bhutan" position="right" width={70} outside={20} />
```

В этом примере изображение занимает 70% prose, float-ячейка внутри колонки — 50%, а оставшиеся 20%
выходят вправо. Для `position="left"` те же 20% выходят влево.

Ручная ширина и группа с общим действием и исключениями:

```mdx
<WrapAround
	position="right"
	width={47}
	textGap="small"
	imageGap="small"
	frame="thick"
	frameColor="alt"
	action="lightbox"
	inlineCaption
	lightboxScope="page"
	images={[
		{ imageId: 'portrait-a' },
		{ imageId: 'portrait-b', action: { type: 'album', albumId: 'iceland' } },
		{
			imageId: 'portrait-c',
			action: { type: 'custom', href: '/courses/', newTab: false },
			caption: false,
		},
	]}
/>
```

## Разрешение данных изображения

Для каждого элемента сборка должна:

1. Найти `imageId` в управляемом каталоге; неизвестный ID является ошибкой сборки.
2. Получить intrinsic dimensions и доступные деривативы.
3. Вычислить подходящие `src`, `srcset` и `sizes` с учётом итоговой ширины блока.
4. Разрешить локализованные `alt` и `caption`, затем применить явные overrides элемента.
5. Разрешить действие элемента: `image.action ?? block.action ?? 'lightbox'`.

Одинаковое разрешённое значение caption используется и inline, и в lightbox; параметры
`inlineCaption` и `lightboxCaption` управляют только поверхностью показа. Обычная inline-подпись
Wrap Around выводится с `opacity: 0.5`; это правило не распространяется на overlay Gallery.

Inline-preview использует поверхность `wrapAround`: из единой лестницы берутся файлы не шире
800 px, поэтому в маленький float-блок не попадают полноразмерные файлы со знаком. PhotoSwipe
отдельно использует `photoswipeSlide` без потолка превью. `sizes` повторяет три состояния CSS:
полную ширину при сложенном float, процент от fluid prose-контейнера и фиксированный максимум от
контентной ширины `648px`.

Правила override:

- отсутствующий `alt` использует каталог и существующий проектный resolver;
- `alt=""` осознанно помечает изображение декоративным;
- отсутствующий `caption` использует каталог и существующие fallback-правила;
- строка `caption` заменяет каталог для этого вхождения;
- `caption={false}` запрещает подпись для этого вхождения на обеих поверхностях.

Если декоративное изображение одновременно является ссылкой, интерактивный элемент всё равно
должен получить доступное имя из метаданных каталога; пустой `alt` не должен оставлять безымянную
ссылку.

## Автоматический подбор ширины

Цель автоматики — выбрать такую долю текстовой колонки, чтобы изображение было достаточно крупным,
но рядом не оставалась узкая, визуально провисающая полоса текста. Для нескольких изображений вся
вертикальная группа оценивается как одна композиция.

Для изображения `i`:

```text
rᵢ = intrinsicWidthᵢ / intrinsicHeightᵢ
```

Для вертикальной группы одинаковой ширины её эффективное соотношение сторон:

```text
R = 1 / Σ(1 / rᵢ)
```

Зазор между изображениями в этой эвристике не учитывается: он влияет на итоговую высоту мало и
остаётся задачей CSS-токена. По `R` выбирается одна из шести проверенных ширин Gutenberg-блока:

| Эффективное соотношение `R` | Автоматическая ширина |
| --------------------------- | --------------------: |
| `< 0.75`                    |                   33% |
| `0.75 <= R < 1.15`          |                   40% |
| `1.15 <= R < 1.55`          |                   45% |
| `1.55 <= R < 1.90`          |                   50% |
| `1.90 <= R <= 2.50`         |                   55% |
| `> 2.50`                    |                   60% |

Границы диапазонов — внутренняя визуально калибруемая эвристика, а не часть контентного API. Их
можно настраивать после проверки на реальном корпусе, не переписывая MDX.

Явный `width` — редакторское решение, полностью заменяющее автоматический процент. Он должен быть
целым числом от 20 до 80 включительно; дробное, нечисловое или выходящее за диапазон значение —
ошибка валидации, а не молчаливый fallback. CSS-ограничения безопасности применяются и к ручному
проценту.

`outside` задаётся целым числом от 0 до 60 и измеряется в процентных пунктах ширины prose. Значение
больше нуля требует явного `width`: автоматическая ширина зависит от геометрии изображения и сделала
бы размер float-ячейки неочевидным для автора. После вычитания должно оставаться минимум 20
процентных пунктов: `outside <= width - 20`. Поэтому `width={70} outside={20}` создаёт визуальное
изображение 70% и float-ячейку 50%, а `width={40} outside={21}` отклоняется валидатором.

## Раскладка и CSS-ограничения

На широком контейнере блок получает выбранную процентную ширину и float по `position`. Процент
считается от фактической ширины контейнера прозы, а не viewport.

В режиме `outside` внешняя float-ячейка занимает `width - outside`, но вложенная группа изображений
сохраняет полную ширину `width` и выступает только к внешнему краю страницы. Фактический выступ
ограничивается свободным пространством между prose и безопасным краем viewport. Когда это
пространство уменьшается, выступ плавно схлопывается, а float-ячейка растёт только до безопасного
предела `max(50%, width - outside)`. После достижения предела уменьшается само изображение, поэтому
текст не получает более узкую колонку, чем в исходной широкой композиции. Без `outside` safe-режим
не применяется. На мобильном полноширинном состоянии выступ всегда равен нулю.

Компонент обязан обеспечивать следующие ограничения:

- минимальную практически допустимую ширину медиа;
- максимум 80% контейнера;
- минимальную оставшуюся ширину текстовой строки;
- safe-предел float-ячейки при схлопывании `outside`;
- переход к `width: 100%` без float, если одновременно соблюсти ограничения нельзя.

Адаптивное решение должно опираться на container query или эквивалентное знание ширины контейнера.
Старый viewport-breakpoint из `_wrap.scss` не переносится буквально: один и тот же блок может жить в
разных по ширине областях страницы.

Точные числовые значения минимальной ширины медиа, минимальной ширины текста и порога переключения
пока не утверждены. Они должны быть site-owned layout tokens и калиброваться вместе с типографикой.
Это не редакторские параметры.

`textGap` использует выразительную шкалу оригинального блока: `none`, `tiny`, `small`, `medium`,
`large` (`0/0.5/1/1.5/2 em`). Привязка к размеру текста сохраняет заметную разницу между соседними
значениями при изменении типографики. В float-состоянии `textGap` задаёт только горизонтальное
расстояние до текста: нижний margin расширял бы область обтекания и оставлял пустую строку под
изображением. После перехода к полноширинному блоку тот же `textGap` становится нижним отступом.

`imageGap` использует те же семантические названия, но
[общую компактную шкалу контентных блоков](README.md#общая-шкала-расстояний) (`0/4/8/12/16 px`)
и всегда разделяет только соседние изображения группы. Старый единый числовой `gutters` и
`distortedGutters` не переносятся: смысл расстояния до текста и расстояния внутри группы различен.

## Несколько изображений

Изображения выводятся в порядке массива и образуют одну вертикальную колонку. Ширина всех элементов
одинакова, высота остаётся естественной; квадратное кадрирование не применяется. `frame` обрамляет
каждое изображение отдельно, а `imageGap` разделяет соседние элементы.

Жёсткого максимума нет, чтобы контракт оставался переиспользуемым. Редакторская рекомендация — от
одного до четырёх изображений. Более длинная последовательность почти всегда должна быть отдельной
галереей, но сама по себе не является ошибкой сборки.

Количество изображений нельзя использовать как отдельный сохранённый флаг. Рендер single/multiple
всегда выводится из `images.length`, поэтому контракт не может попасть в противоречивое состояние.

## Рамка и цвет

Семантические значения рамки соответствуют проверенной шкале текущей темы:

| Значение | Базовая толщина | Скругление |
| -------- | --------------: | ---------: |
| `none`   |               0 |          0 |
| `thin`   |             1px |        3px |
| `medium` |             3px |        3px |
| `thick`  |             5px |        3px |

Скругление повторяет legacy (`$border-radius: 3px` в `bordered-width-and-color`): его получает любая
рамка, кроме `none`. Шкала общая для сайта — `src/styles/image-frame.css`; её же использует картинка
страницы Contacts (`contacts.aside` в `site.yaml`). Толщина может быть оформлена как токены, но смысл и
порядок шкалы должны сохраниться. Цвета не
наследуют всю legacy-палитру Gutenberg. Поддерживаются только два сайт-токена:

```css
--color-image-border
--color-image-border-alt
```

`frameColor='default'` использует первый, `frameColor='alt'` — второй. Сами цвета определяются темой
конкретного сайта.

## Действия по клику

Поддерживаются пять редакторских действий:

- `none` — изображение не является ссылкой;
- `lightbox` — открыть управляемый оригинал/дериватив в PhotoSwipe;
- `photo` — перейти на публичную страницу соответствующей фотографии;
- `album` — перейти в управляемый альбом по `albumId`;
- `custom` — перейти по явно заданному внутреннему или разрешённому URL.

Прямая ссылка на media-файл не переносится. Legacy-значение `mixed` также не является действием:
смешанное поведение получается естественно через общий `action` блока и override у конкретных
элементов.

Валидация действий:

- `photo` допустимо только для изображения, у которого есть маршрутизируемая публичная фотостраница;
- `albumId` обязан разрешаться в существующий доступный альбом;
- `custom.href` обязан пройти общую проверку безопасных ссылок;
- `newTab` по умолчанию равен `false`;
- при `newTab: true` рендер автоматически добавляет безопасный `rel`;
- ни одно действие не должно позволять подменить управляемый источник самого изображения.

## Lightbox: группы и анимация

В lightbox-группу входят только элементы, у которых итоговое действие равно `lightbox`. Изображения
с `none`, `photo`, `album` или `custom` пропускаются, даже если находятся между lightbox-элементами в
массиве.

`lightboxScope='page'` по умолчанию связывает изображения с другими совместимыми lightbox-элементами
страницы. Явный `lightboxScope='block'` создаёт отдельную группу только из подходящих изображений
этого `Wrap Around`. Идентификатор
страничной группы должен быть детерминирован рендером страницы, а не вручную вводиться редактором.

Следующие настройки принадлежат сайту, а не блоку:

- loop;
- переход между слайдами и его длительность;
- стандартная open animation.

Open animation определяется геометрией нажатого превью:

- естественное соотношение сторон наследует сайт-default;
- обрезанное превью (`square`/`rect` в будущем блоке `Gallery`) принудительно использует `fade`,
  потому что zoom из кропа в естественные пропорции визуально прыгает;
- `Wrap Around` не обрезает изображения, поэтому обычно наследует сайт-default;
- стартовый zoom рассчитывается от content-box фотографии без рамки, чтобы border-box не создавал
  короткий сдвиг перед основной анимацией;
- в страничной группе решение принимается отдельно для нажатого элемента, а не один раз для всей
  группы.

Редактор не получает параметр `openAnimation`. Это правило поверхности показа. Оно подтверждено
актуальной логикой `onlyFade` в Gutenberg-панелях и должно быть учтено при проектировании `Gallery`.

## HTML, доступность и progressive enhancement

Ожидаемая семантика — контейнер композиции и отдельный `figure` для каждого изображения;
`figcaption` появляется только при включённом inline-показе и наличии разрешённой подписи. Конкретный
тег внешнего контейнера выбирается по контексту так, чтобы не создавать невалидное вложение в
сгенерированной Markdown/MDX-разметке.

Базовый статический HTML обязан оставаться полезным без JavaScript:

- изображения и inline-подписи видны;
- обычные переходы `photo`, `album` и `custom` работают как ссылки;
- lightbox-ссылка имеет корректный `href` к изображению и может открыться без инициализации
  PhotoSwipe;
- размеры изображения присутствуют в HTML, чтобы не создавать layout shift;
- нативная lazy loading/декодировка и приоритет загрузки выбираются общим image-компонентом с учётом
  положения блока, а не авторятся в MDX.

JavaScript подключается только для элементов с действием `lightbox`. Для float-раскладки, ширины,
рамок и адаптивного переключения он не нужен.

## Рекомендуемая структура реализации

Разделение ответственности должно позволять использовать тот же контракт на следующих сайтах:

1. Схема/валидатор проверяет MDX-параметры, диапазон ширины, IDs и discriminated union действий.
2. Pure resolver получает каталог и превращает авторские данные в нормализованную view model.
3. Pure width resolver вычисляет `R` и одну из шести автоматических ширин.
4. Astro-компонент строит статический семантический HTML через общий responsive image-компонент.
5. CSS отвечает за float, container-query fallback, токены gaps и рамок.
6. Существующий адаптер PhotoSwipe v5 регистрирует только lightbox-элементы и учитывает scope и
   геометрию превью.

Компонент не должен переносить jQuery resize-логику из Gutenberg-редактора или дублировать генерацию
деривативов.

## Проверки реализации

Минимальный набор автоматических проверок:

- схема принимает все defaults, оба положения, границы `20/70` и все варианты union;
- схема отклоняет пустой `images`, неизвестный `imageId`, внешний `src`, дробную/выходящую за границы
  ширину и несуществующие album/photo targets;
- auto width покрыт тестами на каждую границу диапазона и на группы из нескольких aspect ratios;
- ручной `width` полностью заменяет результат эвристики;
- `images.length` корректно формирует single и multiple без отдельного флага;
- block action наследуется, image action переопределяет его, а lightbox-группа фильтрует остальные;
- `caption: false`, `alt: ""`, оба флага показа caption и оба lightbox scope имеют отдельные кейсы;
- natural preview наследует open animation сайта, crop preview принудительно получает `fade`;
- рамка применяется к каждому изображению, а `frameColor` не влияет при `frame='none'`;
- container-level тест/визуальный fixture подтверждает минимальную ширину текста и переход к
  полноширинной раскладке;
- HTML без JavaScript остаётся читаемым и содержит intrinsic dimensions;
- keyboard navigation, focus, accessible names и reduced motion проверяются для интерактивных
  вариантов;
- MDX fixture проходит загрузку коллекции и статический рендер в обеих локалях.

## Открыто перед реализацией

Следующие пункты намеренно не зафиксированы без отдельной визуальной калибровки:

- минимальная ширина изображения и минимальная ширина оставшегося текста;
- названия внутренних CSS/custom-property токенов для толщин рамки и layout safety;
- финальная подстройка порогов auto width на реальном корпусе страниц.

Это внутренние дизайн-токены и эвристики. Их выбор не должен менять публичный MDX-контракт,
описанный выше.
