# Callout

- **Статус контракта:** согласован
- **Обновлено:** 2026-08-26
- **Общие правила:** [контентные блоки](README.md)

## Назначение

`Callout` выделяет важный авторский фрагмент внутри статьи или страницы. Это обычный Markdown-текст
с дополнительным визуальным оформлением: фон или акцентная линия, необязательная иконка и один из
управляемых цветовых тонов.

Основной визуальный пример — фрагмент на странице одного из курсов исходного сайта.
На живой странице он показан как тёмная плашка с круглой иконкой слева.

Историческое имя блока — `Quote`, однако пример не является цитатой из другого источника. Новый блок
называется `Callout` и не использует семантику `blockquote`.

Блок не предназначен для:

- цитат с автором и источником — для них нужен обычный Markdown `blockquote` или отдельный контракт;
- произвольной HTML/CSS-композиции;
- изображений, галерей и других контентных блоков;
- вложенных Callout;
- интерактивного поведения на клиенте.

## Что найдено в исходном контенте

Конкретный экземпляр на странице сохранён не как Gutenberg-разметка, а как старый шорткод
`[quote]`. Для него существует актуальный Gutenberg-приёмник `zu/quote`, поэтому публичные исходные
параметры берутся из Gutenberg-блока. Шорткод нужен только для происхождения и миграционной
диагностики; его устройство и исторические варианты восстанавливать не требуется.

Сохранённые данные и живая страница расходятся:

| Источник                   | Вариант | Цвет    | Иконка  |
| -------------------------- | ------- | ------- | ------- |
| RU в нормализованном дампе | `line`  | `blue`  | `video` |
| EN в нормализованном дампе | `block` | default | нет     |
| Живая страница             | `block` | neutral | `text`  |

Это расхождение не расширяет API. Для визуального примера используется актуальный вид живой
страницы; окончательные параметры каждого локализованного документа выбираются отдельно при
контентной миграции.

По всему сохранённому корпусу найдено 21 вхождение `[quote]`: 14 без параметров, 6 с вариантом или
иконкой, но без явного цвета, и только одно с `color=blue` — рассматриваемый RU-фрагмент. Поэтому
широкая историческая цветовая палитра не переносится.

## Авторский контракт

```ts
type CalloutVariant = 'block' | 'line'
type CalloutTone = 'default' | 'accent' | 'alt'
type CalloutIcon = 'home' | 'image' | 'video' | 'calendar' | 'bookmark' | 'mail' | 'person' | 'text'

type CalloutAttributes = {
	variant?: CalloutVariant
	tone?: CalloutTone
	icon?: CalloutIcon
	transparent?: true
}
```

Текстовое содержимое является телом директивы, а не строковым параметром.

| Параметр      | Default     | Правило                                                              |
| ------------- | ----------- | -------------------------------------------------------------------- |
| `variant`     | `'block'`   | Цельная плашка `block` или спокойный вариант с линией `line`         |
| `tone`        | `'default'` | Нейтральный, основной акцентный или альтернативный акцентный токен   |
| `icon`        | отсутствует | Одна декоративная иконка из закрытого набора                         |
| `transparent` | `false`     | Bare-флаг убирает заливку, но сохраняет структурную границу варианта |

Минимальная запись использует все defaults:

```md
:::callout
Обычный Callout с нейтральной заливкой.
:::
```

Полная запись:

```md
:::callout{variant="line" tone="accent" icon="video" transparent}
Также нас ждут морские пейзажи и маленькие рыбацкие деревни.
:::
```

Эквивалент актуального визуального примера, без утверждения результата будущей миграции:

```md
:::callout{icon="text"}
Также нас ждут морские пейзажи с вершины острова…
:::
```

`transparent` записывается только bare-флагом. Его отсутствие означает `false`; строковые варианты
`transparent="true"` и `transparent="false"` не входят в канонический авторский формат.

## Допустимое содержимое

Внутри директивы разрешены:

- один или несколько непустых абзацев;
- ссылки;
- `strong` и `em`;
- упорядоченные и неупорядоченные списки;
- обычные и явные переносы строк.

Запрещены:

- заголовки;
- изображения;
- таблицы и кодовые блоки;
- произвольный raw HTML;
- другие контентные директивы и MDX-компоненты;
- вложенный `Callout`.

Ограничение намеренное: `Callout` остаётся текстовым выделением, а не универсальным контейнером.
Текст обрабатывается обычным Markdown-пайплайном, поэтому ссылки и inline-разметка не требуют
специального HTML в исходном документе.

## Преобразование Markdown в HTML

`Callout` не является Astro-, React- или клиентским компонентом. Пайплайн сборки:

1. `remark-directive` распознаёт `containerDirective` с именем `callout`.
2. Собственный remark-плагин проверяет имя, атрибуты и дочерние Markdown-узлы.
3. Defaults добавляются в нормализованную build-time модель.
4. Узел преобразуется в статический HTML-контейнер.
5. CSS применяет вариант, tone, прозрачность, иконку и responsive-правила.

Пример результата:

```html
<div class="callout callout--block callout--default">
	<span class="callout__icon" aria-hidden="true"><!-- inline SVG --></span>
	<div class="callout__content">
		<p>Также нас ждут морские пейзажи с вершины острова…</p>
	</div>
</div>
```

Имена классов в примере внутренние и не являются публичным контрактом. Автор не может задавать
`class`, `className`, `id`, inline style или `data-*` через директиву.

Используется нейтральный `<div>`:

- не `<blockquote>`, потому что текст не обязательно является цитатой;
- не `<aside>`, потому что фрагмент может быть важной частью основного рассказа;
- без `role="note"`, потому что блок не обязательно является примечанием.

Семантика дочерних `<p>`, `<ul>`, `<ol>`, `<a>`, `<strong>` и `<em>` сохраняется. Клиентский
JavaScript и Astro island для рендера не нужны.

## Варианты оформления

### `block`

- Default всего блока.
- Цельная заметная плашка на ширину текстовой колонки.
- Геометрия повторяет локальный `_quote.scss`: `min-height: 130px`, внутренние отступы
  `40px 20px 40px 40px`, а с иконкой начало текста остаётся на отметке `110px`.
- Текст имеет размер `1.1em`, вес `500`, межбуквенный интервал `0.5px` и межстрочный интервал `1.25`.
- С иконкой на широком экране резервируется отдельная область слева.
- Правая внутренняя граница адаптируется к ширине prose-колонки: `40px` на широкой колонке и плавно
  уменьшается до минимальных `20px` на мобильном.

### `line`

- Более спокойное выделение с акцентной вертикальной линией слева.
- Текст имеет обычные размер и насыщенность прозы и отображается курсивом.
- При непрозрачном фоне используется слабая тонированная заливка.
- У непрозрачного варианта верхний отступ увеличен до `14px`; transparent остаётся компактным.
- Непрозрачный `default` использует более светлый текст `#f2f2f4`.
- Иконка располагается справа, чтобы не конфликтовать с линией.

В обоих вариантах явные `strong` и `em` внутри текста продолжают работать. Межабзацные интервалы и
списки следуют ритму обычной прозы, но первый и последний дочерние элементы не создают лишнего
внешнего отступа.

## Tone и прозрачность

`tone` является семантической ссылкой на токены конкретного сайта:

| Tone      | Назначение                                   |
| --------- | -------------------------------------------- |
| `default` | Нейтральное оформление Callout               |
| `accent`  | Основной акцентный цвет текущего сайта       |
| `alt`     | Альтернативный акцентный цвет текущего сайта |

Конкретные цветовые значения не хранятся в Markdown. Для текущего сайта `accent` и `alt` используют
согласованные сайт-токены. Залитый `default` повторяет живой оригинал: фон `#4f535e`, белый текст и
белые ссылки; эта пара проходит WCAG AA. У залитого `accent` остаются тёмный текст и тёмные ссылки без
text-shadow. `alt` сохраняет текущую контрастную палитру сайта.

Без `transparent`:

- `block` использует цельную заливку выбранного tone;
- `line` использует слабую тонированную заливку и сплошную линию выбранного tone.

С `transparent`:

- текст наследует цвет прозы;
- `block` сохраняет тонкий структурный контур;
- `line` сохраняет цветную линию слева;
- tone продолжает управлять контуром/линией и иконкой.

Ссылки всегда визуально различимы без опоры только на цвет и используют единое сплошное подчёркивание
толщиной `1px` с отступом `2px`. Старая красная пунктирная стилизация ссылок не переносится. Все пары
текста и фона обязаны проходить WCAG AA. Если
набор токенов сайта не обеспечивает требуемый контраст, проверка темы должна завершаться ошибкой;
браузер не подбирает приблизительный fallback.

## Скругление фона и контура

Радиус является сайт-токеном, а не параметром директивы. Для текущего сайта значение равно `3px`,
как в исходном Gutenberg-блоке.

- `block` скругляет все четыре угла фона или прозрачного контура;
- `line` оставляет левые углы прямыми из-за вертикальной линии и скругляет правые углы;
- круглая подложка иконки всегда имеет полный радиус независимо от радиуса блока.

## Иконки

Поддерживается закрытый набор `home`, `image`, `video`, `calendar`, `bookmark`, `mail`, `person`,
`text`. Историческая опечатка `calender` нормализуется в `calendar` только миграционным адаптером и
не принимается в новых документах.

Иконка всегда декоративная и рендерится с `aria-hidden="true"`: полный смысл должен оставаться в
тексте. SVG поставляются реализацией и не задаются URL, HTML или произвольным именем из контента.

Размещение полностью автоматическое:

- `block` на достаточной ширине — круглая иконка слева как flex-элемент, а не absolute-элемент;
- `line` — круглая иконка справа;
- круг имеет размер `48×48px`, белый фон, рамку `3px`, SVG размером `32×32px`;
- при viewport не шире `768px` размер сохраняется, а круг переходит вправо и выступает над верхней
  границей блока на `21px`, как в оригинале;
- внутренние отступы учитывают иконку и не допускают перекрытия текста;
- без `icon` место под неё не резервируется.

Размеры и breakpoint являются согласованной калибровкой текущего сайта, но не контентным API.

## Ширина, расстояния и адаптивность

- Callout всегда занимает 100% фактической ширины текстовой колонки.
- Отдельных параметров ширины, положения, gap и margin нет.
- Внешние вертикальные интервалы следуют общему ритму прозы.
- Два Callout подряд разделяются стандартным межблочным интервалом.
- При viewport не шире `768px` левый внутренний отступ становится `30px`, размер иконки не меняется,
  а сама иконка выступает над блоком. Правый отступ `block` независимо схлопывается до `20px` по мере
  сужения prose-колонки.

Исторический `contracted` с шириной `90%` не переносится. Он не используется в сохранённом корпусе,
почти не меняет композицию и нарушает общую линию текстовой колонки.

## Валидация

Обработка работает fail-fast:

- неизвестное имя параметра является ошибкой сборки;
- неизвестное значение enum является ошибкой сборки;
- пустое или состоящее только из пробелов содержимое является ошибкой;
- любой запрещённый дочерний узел является ошибкой;
- shortcut-классы и ID синтаксиса directive (`.class`, `#id`) запрещены;
- произвольные HTML-атрибуты запрещены;
- тихого исправления опечаток и fallback к default нет.

Диагностика должна содержать путь к документу и позицию директивы. Defaults применяются только к
отсутствующим допустимым параметрам, а не к их ошибочным значениям.

## Соответствие Gutenberg новому контракту

| Gutenberg / legacy                                 | Новый контракт          | Решение                                                       |
| -------------------------------------------------- | ----------------------- | ------------------------------------------------------------- |
| `quote`                                            | тело директивы          | Строковый RichText заменён обычным Markdown                   |
| `style=block\|line`                                | `variant=block\|line`   | Оба варианта сохранены; новый default — `block`               |
| `color=opacity`                                    | `tone=default`          | Историческое техническое имя заменено смысловым               |
| `color=accent\|alt`                                | `tone=accent\|alt`      | Ссылки на сайт-токены сохранены                               |
| `color=heading\|red\|green\|blue\|violet\|orange`  | ручное решение миграции | Широкая legacy-палитра удалена                                |
| единственный `color=blue` в RU-примере             | `tone=default`          | Согласовано по актуальному нейтральному виду живой страницы   |
| `icon=null`                                        | параметр отсутствует    | Строковый sentinel удалён                                     |
| legacy `calender`                                  | `icon=calendar`         | Опечатка исправляется только при миграции                     |
| остальные поддержанные `icon`                      | `icon`                  | Сохранён нормализованный закрытый набор                       |
| `transparent`                                      | `transparent`           | Сохранён как необязательный bare-флаг                         |
| `contracted`                                       | —                       | Удалён; ширина всегда 100% текстовой колонки                  |
| `bordered=normal\|small\|thin\|none`               | —                       | Внешняя рамка удалена как дублирующая оформление Callout      |
| Gutenberg default `style=line`                     | default `variant=block` | Default изменён редакторским решением                         |
| shortcode `style=line2`                            | `variant=line` + review | Сужение удалено; историческая комбинация не восстанавливается |
| `align=false`                                      | —                       | Выравнивание не является параметром                           |
| `className`, inline styles и произвольные атрибуты | —                       | Запрещены                                                     |

Неподдержанный legacy-цвет, кроме согласованного единичного `blue`, не должен молча становиться
`default`: миграционный инструмент обязан создать запись для ручного решения. Это миграционное
правило не ослабляет fail-fast валидацию новых Markdown-документов.

## Рекомендуемая структура реализации

1. Подключить parser generic directives к Astro Markdown-процессору.
2. Реализовать собственный remark-плагин только для `containerDirective` с именем `callout`.
3. Вынести допустимые атрибуты, defaults и enum в одну строгую схему.
4. Валидировать дочернее Markdown-дерево до преобразования в HTML и сохранять source position для
   понятных ошибок.
5. Преобразовывать валидный узел непосредственно в статический `<div>`, не создавая Astro/React
   island.
6. Рендерить иконки из закрытого локального SVG-набора с единым размерным контрактом.
7. Реализовать variant, tone, transparency, radius, prose rhythm и адаптивность через CSS-токены и
   media query целевого breakpoint.
8. Добавить миграционное преобразование Gutenberg-атрибутов отдельно от валидатора нового синтаксиса.

Парсер директив распознаёт только синтаксис. Значение `callout`, его параметры, HTML и CSS остаются
ответственностью собственного плагина и проекта.

## Проверки реализации

Минимальный набор автоматических проверок:

- `.md` и `.mdx` fixture одинаково распознают `:::callout`;
- минимальная директива получает `variant=block`, `tone=default`, без icon и transparency;
- схема принимает все значения variant, tone и icon;
- bare `transparent` принимается, строковые и неизвестные значения отклоняются;
- неизвестные параметры, class/ID shortcut и произвольные атрибуты отклоняются;
- пустой Callout и каждый запрещённый тип дочернего узла дают ошибку с файлом и позицией;
- несколько абзацев, inline-разметка и оба вида списков сохраняют семантический HTML;
- результат содержит `<div>`, но не `blockquote`, `aside`, `role=note` или клиентский island;
- SVG-иконка имеет `aria-hidden=true`, а без icon место под неё не создаётся;
- block/line, три tone и transparent покрыты структурными или визуальными fixtures;
- `3px` radius текущей темы применяется ко всем углам block и только к правым углам line;
- responsive fixture подтверждает flex-размещение иконки, выступ на `21px` при viewport `≤768px` и
  отсутствие перекрытия текста;
- первый/последний дочерний margin и расстояние между соседними Callout соответствуют prose rhythm;
- ссылки различимы без цвета, а пары токенов проходят автоматическую contrast-проверку WCAG AA;
- преобразователь исправляет `calender`, отображает согласованный `blue` в `default` и направляет
  остальные неподдержанные legacy-цвета на ручное решение.

## Готовность контракта

Синтаксис, содержимое, параметры, defaults, HTML-семантика, визуальные варианты, responsive-правила,
доступность и границы legacy-миграции согласованы. Геометрия иконки и блока откалибрована по
локальному `_quote.scss`; её изменение не меняет публичный Markdown-контракт.
